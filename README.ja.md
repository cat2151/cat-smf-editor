# cat-smf-editor

SMF(Standard MIDI File)を手軽に編集できることを目指している軽量アプリ。[UAPMD](https://github.com/atsushieno/uapmd)を利用しています。Rustで書かれています。

現在、編集はほとんどできないです。
その状況で公開するのはラバーダッキングのためです。

# これまでの課題と、このアプリが解決すること
- [The Mutopia Project](https://www.mutopiaproject.org/) のように、CC0ライセンスの音楽データを公開する試みは、素晴らしいですね！
- 本格的な演奏や、そのための編集には、DAWを起動するなど、前準備が必要なことが多いです。
- 手軽に演奏や編集するための軽量アプリは、操作感覚がnot for meだったりしました。
- 現代は、ほしいUXがあれば、バイブコーディングで実現できます。
- そうすることにしました。

## 機能（AIによる詳細な追記）

- 演奏
  - window titleはアプリ名、SMFファイル名、曲名（先頭track名）、`4tracks`形式のtrack数の順に表示します。未保存の変更がある間はファイル名の直後に`(更新)`を付け、Auto save待機中は`曲.mid(更新)(1分後にauto save)`と表示します。保存後や変更を元に戻したときに消します。左上はPlaying／Stoppedを同じ幅で表示し、再生中は曲先頭からの現在時間、停止中はカーソル位置の時間と小節・beat・tickを同じ場所に表示します。現在時間・合計時間は、曲全体が1時間未満なら`00:00.000`（分:秒.ミリ秒）、1時間以上なら`00:00:00.000`（時:分:秒.ミリ秒）で表示します。合計時間は既存の再生用テンポマップを使い、ミリ秒精度で表示します。再生位置は`32|1|  1`形式で、小節番号は曲全体の最終小節の桁数に合わせて半角スペースで右揃えし、beatだけを既存の拍色にし、tickを半角スペースによる3桁の右揃えにします。Follow・Mixer・Stopの常設表示は省き、`F`・`M`・`Shift+Space`で操作します。`F1`／`?`でhelpを開閉します。
  - `w`で2列overlayを開きます。`wl`で右、`wh`で左の列を操作対象にし、`wj`で操作対象の列を次のtrack、`wk`で前のtrackに置き換えます（端では反対側の端へ戻ります）。`ww`以外は、1列のときは先に2列にしてから効果を出します。2列にすると左に現在track、右に次のtrackを表示します。最後のtrackでは右を先頭trackにし、trackが1つなら左右とも同じtrackです。`ww`で操作対象のtrackを1列に戻します。2列かどうか、左右のtrack、操作対象の列は`status.json`へ保存し、次回起動で復元します。左右の表示時刻は常時同期し、カーソル（再生中は再生位置）を各列の縦中央に揃えます（曲の先頭・末尾付近を除く）。操作対象の列は橙色の枠で示します。`g`でgo overlay、続けて`t`（`gt`）でtrack一覧を開きます。`gt1`はtrack 1、`gt2`はtrack 2、`gt4`はtrack 4へ、goを開く前のカーソル時刻を引き継いで移動します。track 10〜33は`n`・`p`を除く`a`〜`z`、track 34〜59は`Shift+a`〜`Shift+z`で、一覧の各行にキーを表示します。60番目以降のtrackは一覧をクリックして移動できます。`gtn`は次のtrack、`gtp`は前のtrackへ移動し、端では反対側の端へ戻ります。`Ctrl+左`は次のtrack、`Ctrl+右`は前のtrackへ、現在のカーソル時刻を引き継いで同様に移動します（例: 4 trackなら`Ctrl+左`で1→2→3→4→1、`Ctrl+右`で4→3→2→1→4）。2列では`Ctrl+左右`・`gt`・track一覧のどれも操作対象の列のtrackだけを置き換え、反対側の列は変えません。反対側と同じtrackになっても左右とも表示します。`gh`は現在trackの先頭行、`ge`は末尾行へ移動します。`Esc`でキャンセルします。
  - `V`でNotes表示とRaw表示を切り替えます。Raw表示は各イベントの番号・delta・tick・MBT・bytesの右に、Notes表示と同じ内容（ノートは音名・長さ・velocity、それ以外はイベントの説明）を半文字間隔で詰めて並べ、右端にminimapを出します。音名（Note Offの説明内も含む）は鍵盤と同じ12色、meta eventの説明は種類を通常色・中身を紫で表示します。このアプリの専用meta（sequencer-specific）は、byte列でなく`Instrument layers: Organ + Flute (+1 oct, -3.0 dB) · Effects Hall`のように内容を読める形で表示します。Notes／Rawのminimapでは、tempo curveがある場合、conductorのtempo eventの横線をpiano rollのminimapと同じ緑の細いカーブに置き換えます（横軸はBPMで右ほど速く、縦軸は時間）。ノートとほかのmeta eventはその手前に表示します。Notes／Rawのevent list本体とminimapの左ドラッグは、選んだ時間範囲の全trackをA-B repeatします。上下どちら向きにも選択でき、離したときに反映します。event listをつかんでスクロールする操作は廃止しました。minimapの左クリックは従来どおり小節先頭への移動です。2列にしていても、Raw表示中は操作対象の列だけを表示します。
  - `j/k`で行を移動すると、移動先のノート1つだけを試聴し、カーソル行を縦中央に保ちます。クリックでは同時刻の和音を試聴します。`h/l`（`Ctrl+上`/`Ctrl+下`も同じ）で小節を移動すると、現在trackの移動先の小節だけを再生します。`Space`で繰り返す再生方法は変わりません。
  - 再生開始から音声が実際に出始めるまで（plugin準備中）は、開始行に半透明で点滅する`Preparing playback…`を重ね、緑の再生位置線は出しません。
  - 鍵盤の色は調号の主音からの五度圏距離0〜6の7段階で、Monokaiの白・青・紫・緑・黄・橙・ピンクです。調号がなければ灰色です。鍵盤は行の左端・セルの背面へ暗く表示し、押されていない黒鍵は黒で塗ります。鍵盤上の音名とtooltipは出しません。
  - MIDIファイルはコマンドライン引数で指定するか、アプリへdropして直接開きます。引数がなければ前回開いたMIDを復元します。起動時にファイルが開かれなかった場合は、`Ctrl+O`と同じファイル選択を一度だけ自動で開きます。キャンセル後は空の画面になり、ファイルを開いていない間は左上のStoppedとTracksを表示しません。project管理、原本との紐付き、フォルダー探索はありません。
  - `Ctrl+O`でOS標準のファイル選択を開きます。現在のファイルのフォルダを初期表示し、SMF（`.mid`／`.midi`／`.smf`）を選べます。ファイル名入力・`Enter`で開き、`Esc`でキャンセルします。開くと演奏を停止し、キャンセル時も編集内容とカーソルは保持します。選択後はAuto save ONなら保存し、OFFなら通常の未保存確認を行い、読み込み成功後に`pa`相当の全track演奏を自動で始めます。
  - `Ctrl+P`で最近開いたファイルを新しい順の1列一覧に表示します。先頭が`1`で初期カーソルも先頭です。`1-9a-zA-Z`で直接開き（小文字`j/k`の行は`Alt+j/Alt+k`）、`Enter`で選択を開きます。`j/k`・上下矢印は1行、PageUp/PageDownは10行移動して移動先を全trackでプレビュー演奏します。`Esc`で試聴を止めて編集へ戻り、未保存編集とカーソルは保持します。切替を確定したときはAuto save ONなら保存し、OFFなら通常の保存確認を行い、読み込み成功後に`pa`相当の全track演奏を自動で始めます。一覧に「準備中…／準備済み／準備失敗」を表示します。準備済みの音源はファイルごとにアプリ終了までメモリへ保持し、再試聴・確定後の演奏で再利用します。ファイルは毎回読み直し、音色やeffectが変わった場合は必要な音源を準備し直します。各行はキー、最後に開いてからの経過時間、filename、曲名（先頭track名）、演奏時間、track数、fullpathです。経過時間は`1m/1h/1d/1w/1mon/1y`形式で、単位ごとにMonokaiのピンク・橙・黄・緑・青・紫にします。一覧は内容に合わせて自動サイズにし、画面に収まらない場合だけスクロールします。履歴は`%LOCALAPPDATA%\cat-smf-editor\recent-files.json`に保存し、次回起動でも復元します。プレビューは履歴順や日時を更新しません。導入前に開いたファイルの履歴は含みません。
  - `Ctrl+Z`または編集menuの`eu`で、音符・トリル・テンポカーブ・目安BPM、音色・instrument layer・track/master effect・track音量の編集を最大100回戻せます。フェーダーを含むドラッグは1回の変更として扱います。ピアノロール／テンポカーブ・layer画面・ミキサー内でも`Ctrl+Z`を使えます。文字入力中や確認画面、音色／effect browserでは曲のundoを実行しません。undoでは演奏を停止し、戻したSMFから音色・effect・音量の再生用cacheを再構築します。再構築に失敗した場合は曲・再生・履歴を保持します。音色変更で履歴は消えません。redoと履歴の永続化はなく、ファイルの読込成功時に履歴をリセットします。
  - Auto saveはファイルごとに既定OFFで、`,s`または設定overlayの「このファイルのAuto save」で切り替えます。ONにするときは現在の編集内容も含めた保存を確認し、`y`でバックアップ付き保存に成功してからONを確定します。`n`／`Esc`は有効化を取り消し、OFFのまま編集内容を保持します。有効化の保存失敗時もOFFのまま、確認画面から再試行・取消できます。設定変更はSMFの編集として扱います。OFFは直ちに自動保存を止め、OFFの永続化には`Ctrl+S`で手動保存が必要です。設定は先頭trackのtick 0の専用metaへ保存し、OFFではそのmetaを除去します。移動・改名後や次回起動も同じSMFから復元します。ONのファイルでは最初の未保存変更から60秒後に確認なしでバックアップ付き保存し、追加編集で期限を延ばしません。文字入力・ドラッグ・保存確認・ファイル選択やbrowserの操作中は終了まで延期します。ONでは`Ctrl+S`・アプリ終了・ファイル切替時に60秒を待たず確認なしで保存し、終了・切替は保存成功後に進めます。保存失敗時は編集内容を保持してエラーを表示し、定期保存の自動再試行を止めます。終了・切替時の保存失敗は、その操作を止めて`y`で再試行・`n`で破棄して終了／切替・`Esc`で編集へ戻ることができます。`Ctrl+S`の保存失敗は再試行か編集へ戻る操作を選べます。保存に成功すると定期保存を再開します。OFFでは`Ctrl+S`のたびに「y: 上書き保存する」「n / esc: 保存せず編集を続ける」を確認し、編集内容は保存するまでメモリ内に保持します。OFFで未保存編集がある場合は、終了・ファイル切替時に`y`で保存して進む・`n`で破棄して進む・`Esc`で編集を続けることを確認します。保存に失敗した場合は編集内容と確認画面を保持します。
  - 内容変更を上書きする直前に、元の内容を`%LOCALAPPDATA%\cat-smf-editor\backup\`へバックアップします。`foo.mid`ならローカル時刻で`foo_yyyyMMddHHmmss.mid`、同名があれば`.2.mid`、`.3.mid`と連番にします。変更がなく保存不要な場合は作りません。バックアップ失敗時や読み込み後に外部変更された場合は上書きを止めます。世代数制限や自動削除は行わず、整理・復元はuserが行います。音源stateの保存先は従来どおりです。 保存確認ダイアログにはローカル日付で1日1回、バックアップのTIPSと保存先のフルパスを表示します。リンクのクリックまたは`O`でOS標準のopen動作により保存先を開きます。表示日は再起動後も保持します。
  - `,`または右上の`☰`でタイトル`help`の設定overlayを開き、`Esc`で閉じます。表示・音色変更対象・このファイルのAuto saveの設定を行います。
  - ノート行の選択で試聴し、`p` から範囲を選んで再生します。overlayは開始位置を横軸、終了位置を縦軸とするグループで、右ほど開始が早く、下ほど終了が遅くなります。全track対象だけボタンに色を付け、`pa`（全trackを先頭から末尾まで）は右下に置きます。起動時は前回のファイルを開いたあと自動で`pa`相当の再生を始めます。ほかのボタンは現在trackが対象ですが、現在trackにNote Onが一つもない場合は、開始・終了の範囲を保って全trackを対象にします（`pe`もカーソルと同じtickの全trackのノートが対象）。この場合は全ボタンに色を付けます。該当する操作のない枠は空欄です。`pc` は全trackを現在小節から末尾まで、`ps` は現在小節から対象trackの末尾まで、`Space` は最後に使った方法で再生（A-Bリピートの操作では記憶した方法を変更しません）、`pi`は現在の拍だけを再生します。`Shift+Space` は演奏停止です。`pd`（演奏overlay内の `d`／Stopボタン）でも停止し、演奏overlayを閉じます。停止は準備中の再生とA-Bリピートも解除します。`Esc` はoverlayを閉じる操作で、演奏を止めません。`F` はfollow、`M` はmixerです。再生と各trackの音量・muteはeditor自身が扱います。
  - Notes表示でノート行のMBT欄をクリックすると入力欄になり、`M:B:T`を入れて`Enter`でそのノートの開始だけを移します。`Esc`か欄の外のクリックで取り消します。Note Offと他のイベントのtickは変えず、変わるのは移したノートの長さと前後のdeltaだけです。移した先のtickに既存のイベントがあれば、その後ろに置きます。自分のNote Off以降への移動と、同じchannel・音高の別ノートとの前後が入れ替わる移動（別ノートの長さが変わる）は、エラーを出して変更しません。
  - Notes表示でノート行のDuration欄をクリックすると入力欄になり、tick数を入れて`Enter`でそのノートのNote Offだけを移して長さを変えます。Note Onと他のイベントのtickは変えません。移した先のtickに既存のイベントがあれば、その後ろに置き、End of Trackより後ろへ伸ばすとEnd of Trackも同じtickへ動かします。0 tickと、同じchannel・音高の別ノートとNote Offの前後が入れ替わる長さ（別ノートの長さが変わる）は、エラーを出して変更しません。
  - `e`で編集overlayを開き、`em`でカーソル位置のノートのMBT欄、`ed`でDuration欄を、クリックしたときと同じ入力欄にします。カーソルがノート行に無いときは何もしません。
  - `r`でピアノロールoverlay（SMF format 1のconductor trackでは次項のテンポカーブoverlay）を開き、`r`／`Esc`で閉じます。既定ではアプリ内いっぱいに最大化します。`,r`または設定overlayの`Piano roll always maximized`で切り替え、tempo curveの`,m`とは独立して`status.json`へ保存・復元します。OFFでは移動・サイズ変更できます。開いたまま`p`で再生menu、`Space`で前回の再生、`Shift+Space`／`pd`で停止できます。再生menuの`Esc`はmenuだけを閉じ、`r`／`Esc`でピアノロールを閉じても演奏は続きます。演奏位置を橙色の縦線で示し、`F`で横方向中央への追従を切り替えます（曲の先頭・末尾付近を除く）。followは通常画面・tempo curveと共有します。`F1`／`?`でピアノロール専用ヘルプを開き、`F1`／`?`／`Esc`でヘルプだけを閉じます。現在trackのノートはNote OnからNote Offまでを矩形で描き、色はtempo curveと同じ12色です（各ノート位置の調号が基準、調号なしはC major基準）。縦は半音1行（trackの最低音〜最高音の上下に2半音の余白）、横は初期倍率で四分音符96pxで描きます。各枠の左に音高行と揃えた鍵盤を固定表示し、左クリックで押している間、左ドラッグで鍵を移りながら、曲内での使用有無によらずすべての鍵を現在の音色で試奏します（velocity 80）。鳴らしている鍵は既存の12色で示します。鍵盤の外、ボタンを離したとき、画面を閉じたとき、フォーカスを失ったときは消音します。試奏中も曲の再生位置とA-Bリピートを保ち、曲のノートやカーソル位置は変えません。`w`で2 trackを選んでいる場合は、上下半分ずつに各trackを表示します。Note OnからNote Offまであるノートの最低・最高note numberの中央が高いtrackを上にし、同じ範囲中央なら`w`の左右順、ノートのないtrackは下に置きます。各trackの音高範囲をそれぞれの枠に収め、音高zoom・縦scrollは両枠で同じ倍率・移動率を共有します。時間軸・横scroll・minimap・A-B repeatバーの左ドラッグで指定した時間範囲を全trackで繰り返し再生し、右クリック／右ドラッグで近い端を動かします。右ドラッグ中の再演奏は250ms間隔とし、範囲表示は即時更新、離した位置は必ず反映します。バーの左クリックでリピートを解除して現在の再生位置から通常再生を続けます。範囲はtempo end）でその位置から末尾まで再生できます。左ドラッグで選んだ時間範囲が表示幅の90%になるよう拡大します。上半分の右クリック・右ドラッグは表示中の時間範囲の近い端をその位置へ動かし、反対側の端を保って同様に90%へ拡大します。右ドラッグ中は調整範囲を色で示し、離したときに反映します。下半分にポインタがある間、全trackのNote On／Note Offのうちポインタの時刻を左右から挟む最も近い位置に縦線を表示します。Note Onは拍の色を明るさ55%にした破線、Note Offはグレーの実線です。同じ時刻に両方ある場合はNote Onを優先し、片側にイベントがない場合は存在する側だけを表示します。横軸と横スクロールを共有し、音高の縦配置とBPM軸の範囲・拡大縮小は独立しています。下半分の縦軸は目安テンポも含む曲のmin BPM〜max eventで、カーブが無い曲でも既存のtempo eventを水色で表示します。初回表示では既存tempo eventの各位置から表示用の目安テンポを仮生成し、次の目安位置までの水平な破線とBPM値で表示します（先頭にtempoがなければtick 0に既定の120 BPMも作ります）。目安線は左ドラッグの上下でBPMだけを調整し、離したときに保存します。実際のカーブ・演奏テンポと目安位置は変わりません。線とカーブの点が重なる場所では点のドラッグを優先します。初期BPMの速い順の順位も記録し、同じBPMは同順位、順位は1・2・3のように欠番なしとします。現在の目安同士の順位が初期順位と同じ線はピンク、違う線は橙色で、ドラッグ中も色を更新し、順位を戻せば元の色に戻ります。開閉・スクロール・ズームだけではMIDIもUndo履歴も変えず、別のMIDIへ切り替える際の保存確認も出ません。カーブ・目安BPMの変更、またはtrillの変更を確定すると、必要な初期化もその編集とまとめてUndo 1回分にします。各目安と初期順位はconductorのText meta（例: `Reference Tempo: 120 BPM; rank=2`）へ保存し、再表示・再読込では作り直しません。カーブを全削除しても目安は残します。黄の円がテンポポイント、紫の正方形がコントロールポイント（区間ごとに1個の2次ベジェの制御点）です。両種類の点をそのまま左ドラッグでき、近接時はポインタに最も近い点を選びます（完全に重なる場合はテンポポイント）。点の無い場所の左クリックでテンポポイントを追加し、左ドラッグでは追加したポイントをそのまま移動します。円の右クリックで削除します。テンポポイントを隣のポイントにぶつけ、移動できない方向へ500ms押し込み続けると、ボタンを離す前にドラッグ中のポイントを削除します。内側へ戻したり、押し込む方向を変えたりすると500msを数え直します。追加・削除で変わった区間のコントロールポイントは区間の中点（直線）に置き直します。点をドラッグすると上下でBPM、左右でtickを変え、ドラッグ中は書かれるtempo eventを水色でプレビューし、通常の移動は離したときに1回だけ反映します（スナップはありません）。テンポポイントは隣のテンポポイントを越えず、コントロールポイントはその区間の外へ出ません。カーブがある間は、全trackのNote On・Note Offがあるtickとtick 0に、カーブのBPMのtempo eventを書き（直前と同じ値は省きます）、conductorの既存のtempo eventはすべて置き換えます。ピアノロールなど他の編集でノートが動いても、tempo eventを作り直して追従します。カーブはconductorの専用metaへ保存し、再読込で復元します。最後の1点を消すとカーブのmetaだけを除去し、その時点のtempo eventは残します。理由と保存形式は[ADR   - テンポカーブを開いたとき、未登録の曲では全trackからtrillを自動検知して仮表示します。カーブ・目安BPM・trillの実編集時に、ノートのあるtrackへ英語のText meta `Trill Start: {...}`／`Trill End: {...}`を記録します。半音または全音の交互反復が6音以上、64分音符以下の等しいtick間隔で、各Note Offが次の発音位置と一致するものが対象です。開始metaに識別子・channel・2音のnote numberと、検知時の実際のtempo eventで最初の発音間隔を秒へ変換した浮動小数点値を記録します。登録済みなら再表示・テンポ変更後も速度を取り直しません。テンポカーブの曲中にある`Trill Start`／`Trill End`の表示text、またはevent list（Notes／Raw）のtrill metaをクリックすると、そのtrillの編集画面を開きます。`First pitch`の`Upper`／`Lower`で開始音を選び、`First note`で最初の1音の長さ、`Interval`で2音目以降の発音間隔を、秒で個別に入力・ドラッグ変更します。入力・ドラッグのたびにmetaとノート配置を更新し、演奏・A-B repeatも現在の演奏tickから新しい配置で続けます。`Apply`で確定して閉じ、初期化を含めてUndo 1回分にします。値を変えずに`Apply`しても編集扱いになりません。`Cancel`／`Esc`／外側クリックでは初期化・変更・Undo履歴を残さず編集前へ戻します。最初の長さは同じ開始metaの`first_note_seconds`へ保存し、省略時は通常の間隔を使います。実編集と値の変更時に、開始・終了tickを保って、その秒間隔になるようノート数と位置を作り直します。カーブの変更にも追従し、最後の音は終了tickで切ります。ノート位置は整数tickに丸めるため、実際の間隔にはtick精度の誤差があります。管理中のtrillノートの単独移動・長さ変更は拒否し、伴奏の通常編集は維持します。元の開始音と音高ごとの最初のvelocity・release velocityもmetaへ保存し、最初の音を長くして1音だけになった後も復元できます。不正な間隔や同音の重なりはエラーにして変更を取り消します。詳細は[trillの管理と再配置](docs/trill.md)を参照してください。
  - ピアノロールとtempo curveの各描画領域に、全trackのText meta（0x01、例: `Fermata`）をtick位置に表示します。既定は読める本文で、近接するラベルは縦にずらします。`,i`（設定overlayの`Meta text icons`）で小さいアイコンと本文を切り替え、`,a`（`All tracks meta text`）で全track分を一括表示／非表示にします（既定ON）。trillの本文は`Trill Start`／`Trill End`に短縮して表示し、クリックで編集します。アイコンも同じ編集に対応します。どちらもポインタを重ねると元の本文を表示します。両設定は`status.json`へ保存し、次回起動で復元します。

  - mixerはtrackを横に並べ、各列にtrack名・音色名・縦フェーダー・dB値を表示します。音量は−36〜+6 dB、3 dB刻みで、0 dBが元の音量です。`m`で開いた直後はmaster effect欄を選択し、続けて`x`（`mx`）・`Enter`・`Space`でmaster effectのoverlayを開きます。`h/l`／左右キーでmaster／trackを選び、track選択中の`j/k`／上下キーで減音／増音し、マウスでも操作できます。`x`は選択対象のeffect overlay、`f`はSpectrum / Lissajous、`m`／`Esc`はmixerを閉じます。trackが多い場合は横スクロールできます。音量の変更は再生をやり直さず即座に反映され、SMF専用metaに保存して再読込で復元します。MIDI CC7は変更しません。
  - mixerの`Master auto gain`で全track合成後の音量補正を切り替えます。起動時はonで、再生中も切り替えられます。RMS目標は−12 dBFS、補正範囲は−12〜+6 dBで、offは補正なしの音量です。音色・effectを変えても切り替え状態を保ちます。SMFや設定ファイルには保存しません。
  - `Shift+t`またはtrack見出しの音色名クリックで、そのtrackのinstrument layer overlayを開きます。見出しの音色ボタンは全layerの音色名を区切り線でつないだ1つのボタンで、複数layerではlayerごとに色を変えます。一覧は行数に合わせて画面内まで自動で広がり、スクロールバーは表示しません。画面を超える行数ではホイールと選択layerへの自動スクロールを使えます。1行1layerでpatchボタン、整数の`Octave`、`dB`を編集し、`j/k`／上下キーでlayer、`h/l`／左右キーでPatch・Octave・dBを選びます。選択項目は色で示し、`Enter`でpatch browserまたは数値入力を開きます。選択layerを`o/i`でoctave +1/−1、`]/[`で音量 +6/−6 dB、`m/s`でmute/solo切替できます（数値入力中・help表示中は無効）。Octave・dB欄の上でマウスホイールを回すと、その欄を選択して`o/i`・`]/[`と同じ量だけ増減します（数値入力中は無効）。行内の`M/S`でも切り替えられ、有効なボタンを色で示します。soloが0なら全layer、1つ以上ならsoloのlayerだけを鳴らし、追加soloも可能です。muteは常に複数を許可し、soloと重なった場合も消音します。mute/soloは同じtrack内だけに作用し、SMF保存・再読込とundoの対象です。数値欄はクリックでも入力でき、`Enter`で確定、入力中の`Esc`か欄外クリックで取り消します。`a`／`+`は選択layerを複製して末尾へ追加し（空一覧なら既定音色を追加）、`Delete`／行の`−`はlayerを削除します。browserから戻っても対象layerの選択を保ちます。`F1`／`?`で専用helpを開き、`Esc`でhelpだけを閉じます。入力中でないときの`Esc`／見出しの`×`で一覧を閉じます。最後のlayerも削除でき、そのtrackは無音になります。同じpatchを重ねられ、各layerのインスタンスと保持ノートは独立しています。範囲外の移調pitchは鳴らしません。layer gainを合算した後にtrack共通effectを1回適用します。実pluginでの発音・独立した停止、実画面での追加・交換・削除・数値編集と再起動復元を機械検証済みです。パイプオルガンでの音色の良否と操作感は人間による確認待ちです。
  - trackごとのlayerとeffectを復元し、別trackの同pitchも独立した音源で鳴らします。未設定のtrackは従来の既定音色相当のSurge XTを使います。SMFのGM Program Changeを、GM音源としての自動切替やCCの音色選択への解釈は行いません。
- 音色
  - `t`／Program Change行からcat-plugin-playerのpatch browser、effect overlayの`a`／`x`からeffect browserを開きます。最初の1回でplayerを起動して常駐させ、以降はbrowserを前面に出すだけです。patch／effectそれぞれの初回表示までは、画面中央に`now loading...` overlayを表示します。playerのmain画面は表示しません。browserで選んだ音色・effectはplayerでは鳴らさず、editorの音源へ反映します。演奏中はその再生位置から新しい設定で鳴らし直し、停止中は演奏を開始しません。`t`／Program Change行のpatch選択は対象trackの先頭layer、layer overlayのpatchボタンはその行だけを置き換えます。effectはoverlayの`x`では選択中のeffect（無ければ追加）を置き換え、`a`では末尾へ追加します。同じeffect pluginを別のeffect欄へ入れる選択は反映しません。patch browserの左上Role・左下Preset、effect browserの左上Category・左下Kindは、patchは曲・track・layerごと、track effectは曲・trackごと、master effectは曲ごとに独立して`status.json`へ保存し、開き直したときと次回起動で復元します。effectの欄どうしでは同じtrackの選択を共有します。一括patch選択では先頭の演奏trackの選択を使います。検索文字列と、その中に含まれるSolo／Mute・除外条件も同じ対象ごとに保存・復元します。音色を選ばず閉じた場合も絞り込みを記憶します。patch一覧の選択も曲・track・layerごとにpatch名と音源・元patchの識別情報で記憶し、並び順が変わっても同じpatchを選択して見える位置へ戻します。選択の復元では音色を再適用しません。削除済み・絞り込み対象外のpatchは未選択にします。削除されたRole／Preset・Category／KindはALLへ戻します。
  - editorはtrackごとに使ったplugin chainをcacheし、同じ構成へ戻ると再利用します。別の音色ならstateを読み直します。patch／effect browserを開いている間は1分ごとに保持時間を更新し、閉じてから5分使わなければ非使用中のcacheを解放します。使用中の音源は残します。保持中はメモリが増え、初回と解放後は生成時間がかかります。曲切替時は準備済みの音源をファイル別のメモリcacheへ移します。このファイル別cacheはアプリ終了まで保持します。master設定変更、音声エラーなどの音源リセットでは必要な音源を準備し直します。詳細は[インスタンスcache](docs/plugin-instance-cache.md)を参照してください。
  - `t`の対象は`,t`の2択で決め、現在の選択を色で示します。`,ta`（既定）はノートのあるtrackが複数あり、すべてのprogram名が同じ場合に確認なしで一括、それ以外は現在trackを対象にします。`,tc`は常に現在trackだけです。選択は`%LOCALAPPDATA%\cat-smf-editor\status.json`へ保存し、次回起動で復元します。一括ではノートのある全trackの先頭layerのpatchだけを変更し、追加layer、各layerのoctave・dB、各trackのeffect・bypass・音量を保持します。空のlayer一覧には先頭layerを追加します。一括以外ではNote Onがないtrackの音色選択をエラーoverlayで止め、演奏trackを選ぶよう案内します。
  - `Esc`、文字入力に使われない`q`、browserの×、effect browserを閉じるEnterはbrowserを隠すだけで、playerは終了しません。検索欄の`q`は文字入力です。editorを終了するとplayerも終了します。playerが途中で終了した場合はエラーを表示し、次の`t`／`x`で起動し直します。
  - 選択はbrowserを開いたときの対象（現在track、一括ならノートのある全track、masterならconductor）へ反映します。browserを開いた後に別ファイルを開いた場合や、別のbrowserを開いた後、対象layerを削除した後、曲を読み直した後に届いた古いpatch選択は取り込みません。
  - layerのpatch参照・octave・dB・mute・solo、順序付きtrack/master effectの参照とbypassをSMFの専用metaへ保存します。plugin format/IDと元patch位置・program／preset valueで復元し、state本体はSMFに入れません。旧state保存形式の移行は行わず、既知の旧metaや壊れた参照はエラーにします。外部sampleの複製やOS／plugin版をまたぐstate互換は保証しません。
  - 使用したstateは曲やpatchを切り替えても保持し、終了時に`%LOCALAPPDATA%\cat-smf-editor\cache\patch-states-v1\`へ保存します。次回SMF復元では有効なcacheを先に使い、欠けたpatchだけをplayerの非表示生成経路で復元します。全cacheが有効ならplayer探索・起動・カタログ走査・生成は不要で、`--player`の有無にも依存しません。pluginと元patchの更新・破損はcache missとし、octave・dB・track番号はcache keyに含めません。layer間の音源インスタンスは共有しません。詳細と後段の汎用graph移行方針は[ADR 0006](docs/adr/0006-instrument-layers-and-patch-state-cache.md)を参照してください。
- エラー調査
  - 起動・読込・保存・音声・playerなどのエラーを`%LOCALAPPDATA%\cat-smf-editor\error.log`へ時刻付きで追記します。同じエラーが表示され続ける間は毎フレームの重複出力を抑えます。
- エフェクトルーティング
  - master effectはSMF format 1に対応し、conductor（先頭track）の専用metaへ保存・復元します。各trackのeffect・音量を適用して合成した後、master effect、Master auto gainの順に処理します。master effect browserで選んだeffectはmasterだけへ反映します。format 0/2のmaster対応は追加していません。理由と保存形式は[ADR 0004](docs/adr/0004-master-effects-in-conductor-track.md)に記録しています。
  - track effect・master effectは専用overlayで編集します。overlayは信号の流れを縦に描きます（trackはinstrument layer → effect → mixer、masterはtrack群 → effect → Master auto gain → 出力）。effectの追加・差し替え（browser）、ドラッグまたはShift+j/kでの並べ替え、effectごとのbypass、削除ができます。bypassはeffectごとにSMFへ保存し、再生を止めずに切り替わります。入口はメイン画面とmixerの`x`、trackヘッダーとmixerのeffect名です。構成はeditor内の試聴・範囲再生・全track再生で使います。理由は[ADR 0007](docs/adr/0007-effect-chain-on-uapmd-graph.md)に記録しています。

# ローカルでのビルドと実行

editor、`cat-plugin-player`、`uapmd`を同じ親ディレクトリに置きます。editorはplayerの共通host・初回導入のソースを参照し、player用のMML siblingをeditorのビルドには要求しません。playerをビルドする場合はplayer側READMEの依存checkoutも用意してください。

```powershell
cargo build --release --locked
& ./target/release/cat-smf-editor.exe 'X:\music\song.mid'
```

playerを明示指定する場合は `& ./target/release/cat-smf-editor.exe --player 'X:\projects\cat-plugin-player\target\release\cat-plugin-player.exe'` と起動します。環境変数の設定は不要です。

cache missの復元要求とbrowser選択で使うplayerの探索順は`--player <path>`、editorのexeと同じディレクトリ、兄弟repoの`cat-plugin-player/target/release/cat-plugin-player.exe`、`PATH`です。兄弟repoの探索はeditorのexeが`target/debug`または`target/release`にあるときに行い、作業ディレクトリには依存しません。指定したパスが不正なら別の場所へ黙って切り替えません。起動時に未発見なら、[配布ZIP](https://github.com/cat2151/cat-plugin-player/releases/download/v0.1.0/cat-plugin-player-0.1.0-windows-x64.zip)を自動取得し、editorのexeと同じディレクトリへ配置します。取得したplayerの連携機能を配置前に確認し、未対応の古い配布版は配置せず更新が必要な旨を表示します。既存のplayerは上書きしません。playerのライセンス同意画面は出さず、著作権表示はWindowsのDesktop（OneDriveなどへの移動先も含む）へ`cat-plugin-player-LICENSE.txt`として保存します。同名で内容の異なるファイルがある場合は、内容を識別するsuffixを付けた別名で保全します。取得・書込に失敗した場合は再試行または手動ダウンロードを選べます。

起動時に音源を検出できなければ、cat-plugin-playerと共通の画面からSurge XTの利用規約を確認し、同意後にwingetでインストールできます。effectだけの場合も対象です。既存の音源があれば案内しません。playerの音源cacheに実在する音源が記録されていれば起動時の走査を省略します。導入後は再スキャンし、通常のMIDI復元・ファイル選択へ進みます。`あとで`／`Esc`で見送れます。案内を閉じても開始済みのインストールは続きます。Tab／Shift+Tabで項目移動、Enter／Spaceでボタンを選べます。失敗の詳細は画面と`error.log`へ出し、wingetがない場合は手動取得先を案内します。player選択のエラー画面の`Setup`からやり直すこともできます。ZIPの配置先には書込権限、Surge XTの導入にはWindowsの権限確認が必要な場合があります。構成は[ADR 0009](docs/adr/0009-first-run-dependencies.md)を参照してください。

各アプリは自分のbuildに対応するhost DLLをexeへ同梱します。editorのDLL展開先は`%LOCALAPPDATA%\cat-smf-editor\cache\native\`です。`cache/`配下は再生成可能なデータだけで、削除後は必要なものを再生成します。設定・前回の操作位置・browser選択を持つ`status.json`、`settings.toml`、履歴、ログ、MIDI保存時の`backup/`はcacheの外へ保持します。editorはインストール済みplayerのDLLを借りません。共通化と保存契約は[ADR 0003](docs/adr/0003-shared-host-player-selection.md)、配布の構成は[release workflow](docs/release-workflow.md)を参照してください。
