# ADR 0017: GMの4行方式とkitを共有する実note方式を併存させるドラム編集

- 状態: 採用
- 決定者: user（Surge XT、4行、16step、GM番号と再生先番号の分離、既存catalog分類の優先、4行方式を保ったkit共有の追加、player側browserでのkit選択、新規kitの既定音色とfallback、kit行の4音初期配置と空欄行追加・note差し替え）
- 関連: [0006](0006-instrument-layers-and-patch-state-cache.md)

## 目的と判断

小さいドラム編集から始めるため、userはKick・Snare・Hi-Hat・Percussionの4行と、16分音符16stepのmatrixを指定した。16stepごとに前後へ移動し、GM番号は36・38・42・39、各行の再生先は初期値60の編集可能な番号とする判断をuserが選んだ。当初は拍子によらず四分音符4拍分を1ページとした。その後、userは小節番号表示と表示小節のA-B repeatを求め、4/4以外も実際の小節・拍子に合わせる判断を選んだ。表示と再生範囲の意味を一致させるため、現在は1ページを実際の1小節とし、16分音符のstep数を拍子から求める。

既存instrument layerは独立したinstanceと音色参照を復元できるが、全ノートを全instanceへ配送する。音色管理はそれを共有し、ドラムtrackでは行に対応するGM番号のNote OnとNote Offだけを指定先番号へ変換する。通常layerの配送は変えない。SMFのノート自体を音色固有の番号へ書き換えるとGMとしての意味が失われるため、変換は再生時に限る。

音色をPercussionフォルダーから探す案に対し、userは既存catalogのkick／snare／hi-hat／percussion分類を優先するよう補足した。TUIの共通分類はcatalogのカテゴリと表示名を使い、具体的な部位をPercussionより先に排他的に分類している。その処理をcrateとして再利用し、Surge XTに絞った候補を使う。editor独自のキーワード表やフォルダー分類は設けない。最初の対象をSurge XTに限定することと、分類規則をSurge専用にすることは分ける。Percussion行からは、実測で音高がnoteについてくる音色（共有表`patch-pitch-tracking.json`でtrue）を外す。patch browserはそれらをleadに並べるため、外さないと行の初期音色とbrowserの欄が食い違う。照合はcat-plugin-playerと同じ`cmrt_patches::pitch_tracking`を使い、表が取れなければ外さない（[cat-plugin-player ADR 0040](../../../cat-plugin-player/docs/adr/0040-measured-pitched-percussion-categories.md)）。

userはEnterとhjklの往復では入力効率が悪いと報告し、左手のキーとSpaceをnote toggleへ優先するよう求めた。行はKickを最下段にし、4stepの区切りを視覚的に示す。音色の比較も編集の反復に含まれるため、独自の候補dialogを廃止して通常のpatch browserを行の分類で開き、選択中もSolo／全trackのA-B repeatを維持する。

## Kitを共有する追加方式

4行方式は部位ごとの独立音色を差し替える目的に合う一方、kit内の多数の音を探して編集する用途では4音に限られ、同じkitのinstanceが重複する。userは4行方式を残し、既存catalogのkitを1音源で共有する方式を追加する判断を選んだ。4行のNote候補を増やすだけの案と、単体previewを別窓で開くだけの案は、複数noteの編集と1つのkitの相互作用を満たさないため採らない。

kitでは行位置をnoteの意味に使わず、実際のMIDI noteを1つの指定layerへ送る。通常layerの全note配送と4行のGM変換は維持する。当初はcatalogの割当と既存hitの和集合をすべて行にし、kit交換で既存hitを別の行位置へ置換しない方式を採った。新kitで鳴らない音があり得ても、その編集内容を隠したり削除したりしない。行の名前は原典を保存し、欠落した名前をGM名から推測しない。

128音を並べる方式では、userが必要とする36と38へ到達するだけでもスクロールが必要だった。userは今回のkickを最下段へ置くことを自然と感じており、固定の番号順より、使う音の配置を保って編集できることを優先した。kit内の候補一覧とgridの行割り当てを分け、初期配置は上から49・42・38・36の4行とし、必要なときに空欄の4行を上へ追加する判断を選んだ。空欄は音を出さず、行の番号から現在kitのnoteを検索・試聴して割り当てる。kit全体の選択はplayerが担当し、行の割り当てはeditor内で同じkit音源を使うため、音を差し替えるたびに別アプリへ移動する必要がない。名前は引き続き原典を使い、既定番号が別の音に対応するkitでGM名を偽って表示しない。

行のnote変更は、表示だけを切り替えて元のhitを見えなくする案を採らず、userの承認によりコンテナ内の各patternを含む既存hitの音も差し替える。発音位置とvelocityを保ち、割り当てとhitを一緒にUndoできるようにする。同じnoteの行が重なるとどちらの行を編集したか区別できないため、別行に割り当て済みのnoteは選択候補から外す。行の割り当てを音色情報とは別に保存し、kit全体の交換で行配置を失わない。以前のkit曲では既定4音以外の入力済みnoteも行に残し、表示方法の変更で編集内容を隠さない。

音色候補・重いkitの明示ロード・state生成は既にplayer側が持つため、editorにcatalog readerや別のkit pickerを設けない。userが選んだplayer側browserから、同じ選択の音色参照・state・note情報を一体で返す。候補移動と試聴では曲を変更せず、対象と要求世代が一致した明示確定だけを適用する。試聴の音源と終了処理は曲の演奏から分け、取消や古いload完了で曲の音色を変えない。editorでの単note試聴には行の入力velocityを使う。

Virtual MIDI keyboardの新規containerがInit Sawに固定されていたことに対し、userは通常・Drum・Drum Kitの3種類から選ぶことを求めた。Init Sawや4行の既定音色と同じく、種類を選ぶだけで作成を完結させるため、kitだけ追加の音色選択を要求する案は採らない。userはMind Game.sfzを既定とし、不在時はSpaceによる明示ロードが不要なkitの先頭へfallbackする判断を選んだ。候補順とSpace要否はplayerの既存catalogと判定を使い、editorへ別の選択規則を複製しない。新規containerだけを追加し、pattern作成や別画面への遷移は伴わせない。

kit情報は共有instrument layer設定に追加し、音色は従来の参照とstate cacheへ、hitは実noteのNote On/Offへ保存する。stepをmetadataにも保存する案は二重管理になるため採らない。入力velocityの変更は以後の入力だけへ適用し、既存hitのvelocityは個別編集とUndoの対象にする。4行とkitの設定が同じtrackに付く状態は拒否する。kitの行別gain・FX・mute・swingは1音源の制御と一致しないため追加しない。Virtual MIDI keyboardでのkit演奏・録音対応はuserの確定要件とし、未対応の間は4行前提の入力をkitへ流用しない。新規containerの3択化と演奏・録音対応は分けて実装する。

## 保存と既存データ

音色参照は既存のinstrument layer metaへ、4行とlayerの対応・再生先番号は同じtrackのtick 0専用metaへ保存する。step状態を別のpatternとして重複保存せず、通常のGMノートを編集対象にする。既存のstate cacheと再起動時の復元経路を共有し、catalogは音色選択と新規作成にだけ必要とする。

導入時の起動対象SMFとローカル設定の読込経路には、新しいdrum metaが存在しなかった。既存schemaを置き換えず、metaのない曲は通常layerとして扱うため、一度限りの移行は不要である。ドラム作成は独立trackへの追加を基本とし、既存の旋律や音色を置き換えない。当初の固定durationは、次のnoteまたは小節末尾まで伸ばすというuserの指定で置き換える。既存noteの発音位置・velocity・音色参照は保ち、Note OffをUndo可能な編集として再計算する。継続利用中の起動対象SMFには既にdrum metaがあるが、保存schemaと行の識別順は変えないため形式移行は不要である。追加時のvelocityは100とし、この4行方式には4種類以外のGM番号を追加しない。kit方式は別の保存契約で実noteを保持し、既存4行の識別順・metadata・音色参照を変えない。旧曲を保全した上で通常の読込・復元を確認する。旧形式の変換は行わず、新kitの検証には別曲を使う。行配置はkit情報への任意項目として追加するため、保存済みのnote/name・hit・音色参照はそのまま読める。配置のない曲は既定4行と入力済みnoteから配置を求め、原本を一括変換しない。
