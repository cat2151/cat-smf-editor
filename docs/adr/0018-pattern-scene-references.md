# ADR 0018: same measure・pattern・Scene／SongをSMF内の参照として扱う

- 状態: 採用
- 決定者: user（同じ小節への参照、take比較、3窓の作業領域、音色入れ物とpatternの所属、専用trackへの保存、配置レーン・Scene・Songをconductorのmeta 1個に集約、発音単位、演奏表現と競合・復元・移動の規則、patternが無い曲での開始）
- 関連: [0006: instrument layerと音色参照](0006-instrument-layers-and-patch-state-cache.md)、[0010: 通常のMML・コード入力](0010-mml-chord-note-insertion.md)、[0013: 安定した所有元への参照](0013-instrument-parameter-automation.md)、[0017: ドラム編集](0017-drum-sequencer.md)

## 参照を保存し、本体の変更へ追従する

同じ小節を繰り返し使い、元を変更したら各出現へ反映したいという要求から、same measureは同じ通常SMF trackの小節番号への参照とした。音符を各出現へ複製して保存すると、本体の変更と複製先の同期が別の編集になる。参照をSMF専用metaに保存し、音符は再生用sequenceを構築する前に展開する。audio callbackで曲を探索せず、保存用の曲へ展開結果を書き戻さない。参照するのは音符だけとし、音色・tempo・CC等の複製は行わない。

参照連鎖、異なる小節長への伸縮、小節をまたぐ音符の切詰めやtie推測は扱わない。元の内容を無断に変えず、何が鳴るかを小節単位で決められる範囲に絞るためである。通常音符や別参照との重複は二重発音になるため拒否し、一括生成も全件検証後に反映する。空小節も小節末までの無音として保持し、最後の参照metaの位置で再生が終わる解釈は採らない。

take比較では小節番号だけで本体を識別せず、patternへ永続IDを与える。本体は専用trackの通常MIDIイベント、識別と配置は専用metaとして、同じSMFを正本にする。設計開始時は1track・1小節を単位に考えたが、熟議で音色入れ物に複数のpatternを所属させ、各patternが複数小節を扱う形に整理した。独立pattern DBや保存用の展開音符を併置せず、既存のnote編集・MML・Undoを利用する。共有本体の変更は全参照へ、複製したtakeの変更はそのtakeだけへ作用する。参照中の本体削除を拒否し、行番号やtrack配列の変化で参照先が別物にならないようにする。

## 配置レーンと発音先を分離する

設計開始時は既存の曲編集へ小さく接続するため、通常SMF trackの小節へpatternを適用してその音色で鳴らし、Sceneも配置済みの曲範囲から作って順序リストで比較する案を考えた。しかし、userが求めるのは曲への事前配置なしに部品を組み立て、複数レーンへ並行して配置する作業領域であり、熟議の早い段階でこの案では要求を満たさないと気づいた。そのため、通常track一覧や1本の順序リストによる代用をやめ、独立した配置レーンを設ける。

配置レーンは部品を置く座標、発音先は音色設定の所有元として責務を分離し、配置レーンを発音先の入れ物trackとは別に保存する。Sceneは長さと内部レーンのpattern配置を持ち、SongはpatternまたはSceneへの参照を配置する。共有Sceneの編集は全出現へ反映し、ある配置の移動・解除では本体を変更しない。同一レーンの時間重複は拒否し、別レーンの同時演奏を認める。空白や末尾の休止を詰めると比較する曲構成が変わるため、Sceneの長さも明示的に保持する。

本体の保存用trackを通常合奏へ混ぜると配置先と二重発音するため除外する。Scene／Songの再生も選んだ配置だけを展開し、元の通常曲や本体全体を重ねない。配置レーンを発音先trackへ読み替えず、レーン移動で音を変えない。単体試聴とScene／Songでは同じ発音設定を使い、tempoは配置後の曲位置で評価する。参照欠損や長さ不一致は再生前に拒否し、部分的な展開で成功したことにしない。

## 通常編集を保ち、試聴と配置を分ける

保存先sourceを選んでからpatternを作る案は、保存上の都合を入口に持ち込み、気軽にtakeを作って比較する目的に合わない。発音設定を共有する音色入れ物の選択を入口とし、その配下でpatternを作成・編集する。曲やSceneへの配置は別の明示操作に分け、候補を聴き比べるだけで配置や編集中の本体が変わらないよう、試聴候補、本体編集対象、各matrixの配置先を別の責務として保持する。

patternが1つも無い曲でpattern作業を始めた場合は、空のScene／Songを見せず、入れ物の選択から最初のpatternのMML入力まで1つの流れで進める（user）。user が選んだのが一覧を開く操作でも、作る物が無ければその一覧は使えないためである。

その作業を一時的なmodalの往復だけで代用せず、userの選択によりSceneとSongを同時に表示する。各窓の選択・入力所有者は独立させ、再描画でrootの編集中入力からfocusを奪わない。補助窓が入力dialogを覆わないよう、個々の窓に例外を足すのでなく共通の入力所有権で制御する。

Notesではpatternの本体範囲を通常編集へ投影し、本体への対応を通して書き戻す。一方、Rawは保存用SMFの実eventを直接編集する。表示列だけをRawへ変えて投影を残す方式は、表示と編集先を食い違わせるため採らない。表示・実eventの対応・編集権限を共通の境界で決め、mode切替だけでは曲やUndoを変えない。

編集Contextや独立した表示フラグだけでmodeを決めると、表示切替やtrack移動でNotesと実trackの役割が食い違うため、両者からpattern modeを導出する。有効な本体と対応付けを要求する編集権限は別に保ち、modeが有効なだけで本体の保存用trackへ直接書き込めるようにはしない。overviewを閉じる際も、この規則との整合をRawへの暗黙切替で取らず、userの指定によりNotesを維持して通常trackへ移る。

## 音色入れ物がpatternを所有する

設計開始時は、配置先から音を独立させるため、patternごとに通常SMF trackの安定IDへの任意参照を持たせ、未指定時はInit Sawを使う案を考えた。userの指摘を受けて熟議し、参照を選べるだけでは共有する音色の編集単位が明確にならず、patternごとに音色を作り込むうちに意図せず分岐するリスクを防げないとすぐに気づいた。この設計上の誤りを避けるため、先に共有する音色入れ物を定め、その配下にpatternを作る関係とする。

userは、先に音色を選んで配下のpatternを作る順序を示し、さらに共有対象を、音色を変更できる「音色入れ物」として明確にした。入れ物が同一性を持ち、patchはその変更可能な設定とする。同じpatchを選んだだけで別の入れ物を同一視せず、入れ物の発音設定を変えると配下の全patternとその全配置へ反映する。patternを複製しても所属は共有し、独立した音色が必要な場合だけ入れ物を明示的に分ける。

入れ物は単一patchに限らず、layerやドラム4行を含む発音設定一式を所有する。初期の入れ物はSurge XTのInit Sawと、既存Drum Sequencerの4音色を設定したドラム用の入れ物とする。音色の基準設定であるpatch参照、layer、macro固定値、effect、gain、ドラム行の対応は入れ物へ、音符、velocity、CC、pitch bend、parameter automationなどフレーズに伴う演奏表現はpatternへ置く。既存のpatch参照とstate cacheによる復元を利用し、patternごとの音源snapshotは作らない。

## 入れ物を専用SMF trackへ、配置をconductorへ保存する

この所属関係を保存モデルでも一意にするため、userは1つのMID内で、1つの音色入れ物とその配下のpattern群を1本のpattern mode専用trackへ保存する方式を選んだ。入れ物trackは安定IDと発音設定を持ち、各patternは安定ID、名前、本体の保存範囲、長さと拍子構成を持つ。所属は格納先trackだけで決まり、patternごとの音色指定や通常trackからの音色借用は設けない。本体イベントは通常MIDIイベントとして保持し、同一track内のpatternの保存範囲は重複させない。

Scene用・Song用の配置レーンとその配置は、track 0（conductor）の先頭にある専用meta 1個へ、Scene・Songの定義とまとめて保存する。レーンごとに専用trackを設ける案は、レーンを足すたびにtrackが増え、MIDとして扱うtrack一覧・再生・一括操作のすべてでレーンtrackを除外する分岐が要るため採らない（user）。Sceneはレーンとpatternへの配置を、SongはレーンとpatternまたはSceneへの配置を持つ。レーン・配置にも安定IDを与え、名前・配列index・本体の保存位置で参照先を識別しない。配置をeventとして持たないため、位置の正本は小節番号とする（Scene内は0始まり、Song内は1始まり）。tickは保存せず、拍子構成から導出する。そのため拍子を変えても配置は同じ小節番号に留まり、その小節の拍子がpatternと合わなくなる変更は拒否する。Sceneの名前、長さ、拍子構成、レーン順と、Songの長さ・レーン順も同じmetaに保持し、空の構成や末尾の休止も表現する。

patternは複数小節を扱い、新規作成時は1小節とする。入れ物track内のtickは格納座標にすぎず、pattern内部は先頭を0とした時間、SceneレーンはScene先頭からの時間、SongレーンはSong内の時間として扱う。格納位置の変更で音楽的な意味が変わらないよう、patternの長さ・拍子構成をその格納位置や最後の音符から推測しない。tempoはSong側で持ち、配置後の曲位置で評価する。単体試聴では明示した試聴tempoを使う。配置による伸縮は行わず、配置先と小節構造が合わない場合や、長さ変更で配置が衝突する場合は拒否する。

入れ物trackの本体を通常合奏へそのまま混ぜず、Scene／Songの配置参照から展開する。Sceneレーンも、所属Sceneが参照された場合か単体試聴の場合にだけ展開する。この除外は当アプリの再生規則であり、通常MIDIイベントを読む他のplayerへは伝わらないため、編集用MIDの保存と、配置を展開した演奏用SMFの出力を区別する。

演奏用出力にはSongの展開結果だけを発音先ごとにまとめ、編集用の本体・配置参照を混ぜない。native parameterは標準MIDIのCCへ一意に置き換えられず、離れた制御区間を連続curveへ結ぶと休止中の基準値や境界の切替が変わる。そのため、通常MIDIイベントを展開しつつ、native parameterの区間と基準値は専用metaへ保持する。この表現と音色参照の復元は当アプリの契約とし、他playerでの完全な音響互換を出力の意味に含めない。

## 入れ物単位の発音と演奏表現の競合を定める

userは、同じ入れ物に属するpatternの同時配置を一組の音源・effectへ合流させる方式を選んだ。配置ごとに発音instanceを分けず、複数patternが一つの楽器を演奏するものとする。そのため、あるpatternによるparameterやCCの操作は、同じ入れ物で同時に鳴る他patternの音符にも作用する。独立した制御が必要なら入れ物を分ける。

同じ制御対象に異なる値を要求するpatternを、レーン順や後勝ちで処理すると配置の並べ替えで演奏が変わる。このため、同じ制御対象を含むpatternの配置期間が重なる場合は拒否する。対象はparameterならlayerとparameterの安定ID、CCなら実際の配送先・channel・CC番号などで識別する。占有期間は値を変更する瞬間だけでなく、その制御を含むpatternの配置期間全体とする。音符のみの重なりや別対象の制御は許可し、本体編集でも影響する全配置を検証して競合を確定前に検出する。

再生順や途中再生で結果が変わらないよう、制御終了時は入れ物の基準値へ戻す。任意CC等の基準値を音源から取得できるとは限らないため、使用する制御には入れ物側で明示的な基準値を持たせ、取得不能な値を推測しない。同じ対象を操作する次patternが直後に続く場合は、その開始値へ直接切り替える。途中再生・repeatでは、その位置の制御値を再構築してから発音する。

Note Onはpattern内、Note Offは末尾と同tickまでを許可し、pattern境界をまたぐ音符は当面拒否する。音符の長さと音響的な余韻は区別し、音源のreleaseやeffectの余韻をpattern末尾で強制的に切らない。

## 所属変更の参照を維持し、内容を保全する

所属移動は選んだpatternだけを別の入れ物へ移す操作とし、移動元の全patternを移す意味にはしない。pattern IDは維持するため、そのpatternを参照するScene／Songの全配置が移動先の発音設定を使い、移動元に残る他patternには影響しない。ある配置だけ音色を変える場合は、本体を複製して別の入れ物へ移し、その配置の参照だけを差し替える。

移動先でparameterやドラム行などをそのまま解釈でき、全配置で新たな制御競合が生じない場合だけ所属変更を許可する。対応しない演奏表現を黙って削除したり、別対象へ推測で割り当てたりせず、不適合なら元の所属と内容を保ったまま全体を拒否する。音符だけを取り出す操作は、所属移動とは別の明示操作とする。

userは全userのpattern関連データを削除済みと明示したため、設計初期の試作データからの移行処理や互換層は不要とする。この判断はpattern関連データに限り、通常曲・音色・設定など他の既存データの削除や変更を許可するものではない。保存レコードの具体的なフィールド構成は、この責務と不変条件を満たす実装設計で定める。
