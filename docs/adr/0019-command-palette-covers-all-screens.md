# ADR 0019: コマンドパレットは全画面の全機能を出し、必要なら画面を移って実行する

- 状態: 採用
- 決定者: user（どの画面のパレットにも全画面の全機能を出す、画面遷移が要る機能は自動で遷移して実行する、実行後は遷移先に留まる、同じ機能は今いる画面のもの1つだけ出す、どの窓でもアプリ終了を出す、「アプリ終了」と「閉じる」を言葉で区別する、日本語説明をホバーまたは選択中のF1で表示し、説明もMigemo検索の対象にする、機能名・tooltip・画面名・検索語を1つのTOMLへ置き、Rust側の機能名を削除する、機能名は`name`の1欄にする、正本はrepoの`config`に置く、読み込みはパレットの表示まで遅延する、idは`<対象>.<操作>`にして履歴は引き継がない）
- 関連: [0018: Pattern／Scene／Song](0018-pattern-scene-references.md)

## 候補は画面ごとの手書きリストで決めない

userの意図は、パレットを開けばどの画面の機能も見つかり、選べばその画面へ移って実行されることである。画面ごとに「他のどの画面の機能を混ぜるか」を手書きのリストで持つ方式は採らない。リストに無い画面の機能が候補から漏れ、漏れを埋めるために同じ機能を別の画面へ写すことになるためである。写した機能は片方だけ直ると挙動が食い違う。Song窓にEvent listの機能が出ず、Pattern操作がEvent list・Scene・Songに同じ物として3回登録されていたのは、この方式から生じた。

候補は、今いる画面の機能、遷移できる全画面の機能、画面に属さない機能の和とする。遷移できる画面は、入力中の一時窓とapp全体のdialogを除くすべての画面である。Scene／Song窓は、その窓が開いているときだけ遷移先に含める。窓が無いときの入口は「Pattern / Song」1つにする（0018の、空のScene／Songを見せない規則に従う）。

## 名前だけで伝わらない対象と効果を日本語で説明する

「Audition tempo」の対象と意味が分からずuserが混乱したため、userは日本語のtooltipをホバーまたは選択中のF1で表示する方式を選んだ。説明の常設・自動表示で候補を埋めず、キーボードからも必要なときだけ読めるようにする。説明は短い名前の言い換えに留めず、何を対象に何が変わるかを伝える。ただし、分かりにくい仕様そのものを説明で正当化せず、試聴tempoの見直しは0018で扱う。

説明も既存のMigemo検索へ含め、名前を知らなくても「試聴」「shichou」や複数語で探せるようにする。説明を検索対象に加えるだけでは、最近使った操作の説明に語が含まれるだけで、名前で探した別の操作より上に出る。この食い違いを避けるため、同じ検索語で選んだ履歴を最優先とし、それ以外では名前・キー・既存の検索語への一致を説明だけの一致より優先する。各組の中では全体の選択履歴と定義順を保つ。

## 入力中の一時窓では、その窓の機能だけを出す

MML・Note・歌詞などの入力窓、確認dialog、範囲選択中は、その窓の機能（とapp dialog以外では画面に属さない機能）だけを候補にする。入力の確定・取消を経ずに別の画面へ移ると、入力内容が宙に浮くためである。同じ理由で、root窓が入力中のときにpane窓からroot側の機能を選んでも実行しない。

## 遷移して実行し、遷移先に留まる

今の画面の上に重ねて開く組（Timeline・Track Overview上の設定menu・再生menu、Mixer上のエフェクトなど、従来から重ねて使っていた組）は重ねて開く。それ以外は、各画面の「閉じる」操作でEvent listまで戻ってから目的の画面を開き、その画面の機能を実行する。閉じる処理を遷移用に別に書かないのは、各画面を閉じたときの後始末を1か所に保つためである。目的の画面に着けなかった場合（ドラムtrack作成の確認が出たなど）は、機能を実行せずにその場に留める。

実行後に元の画面へ戻す案は採らない（user）。pane窓からroot側の機能を選んだときは、root窓へfocusを移す。

## 同じ機能は1つだけ出し、keyを持たない共通機能は1か所に登録する

停止・Help・Notes/Rawのように複数の画面にある同じ機能は、今いる画面のものを1つだけ候補にする（user）。keyは画面ごとの割り当てなので、keyを持つ機能は各画面に登録したまま、候補の段階で1つにする。他の画面の「閉じる」は、開いてすぐ閉じるだけで何もしないため候補に出さない。keyを持たず、どの画面で実行しても同じ動作をする機能（Pattern操作、Scene作成など）は、画面に属さない機能として1か所だけに登録する。

## アプリ終了はどの窓からも選べる

pane窓・help窓を含むどの窓のパレットにも「アプリ終了」を出す（user）。pane窓の「閉じる」と取り違えて、アプリを終了する手段が見つからない状態にしないためである。アプリを終了する機能は「アプリ終了」、画面や窓を閉じてEvent listなどへ戻る機能は「閉じる」と書き、「終了」単独では書かない（user）。

## 文言はTOMLの1ファイルに置く

パレットの機能名・tooltip・画面名・検索語は`config/command-palette.toml`だけに置き、Rust側に機能名の文字列を持たない（user）。AI生成の文言が読みづらいので、開発者が1つのファイルを編集するだけで、再起動なしに直せるようにするためである。直す場所は、パレットに見えている文字でファイル内を検索して見つける。

形式はTOMLとし、mdに説明を置く方式はやめる（user）。mdでは見出しで操作を指すので、見出しと実際の表示名がずれても検出できず、説明のある37件中13件が食い違っていた。機能名は`name`の1欄で、英語でも日本語でも書ける。`name_en`／`name_ja`に分ける案は採らない（user）。

文言の違いはid側で表す。状態で名前が違う操作は状態ごとに別のidへ分け、画面で違う文言は`screen`付きの項目に書き、動的に増える行は`text_id`で1項目を共有する。実行時の値が名前になる行（trackや最近開いたファイルなど）だけは、コードが付けた名前を使う。VOICEVOX／ずんだもんの別名もコードで判定せず、`search`へ書く（user）。そのため、名前が実行時に決まる行には別名が効かない。

正本はrepoの`config`に置き、AppDataにもexeの隣にも置かない（user）。`target`配下のexeだけがこのファイルを読み、それ以外のexeはファイルを探さず、exeに埋め込んだ同梱分を使う。exeだけの環境でも全文言が出る。

場所の判定と読み込みは、パレットの表示で必要になるまで遅延する（user）。起動時とパレットが閉じている間は行わない。`definitions()`は毎フレームのキー処理から呼ばれるので、読み込みと適用をそこへ入れない。

文法エラー、idの重複、未知の画面があるファイルは丸ごと採用せず、前回の内容を保ってエラーを表示する。編集中の打ち間違いで文言が消えないようにするためである。定義の無いコマンドはidを名前に出して落とさず、漏れはテストで検出する。

idは読むだけで操作が分かる`<対象>.<操作>`の形にする（user）。履歴はidで操作を識別するので、改名した操作の履歴は引き継がれない。利用者は作者だけなので、互換より長期的な開発体験を優先し、移行処理は作らない（user）。helpとdialogの見出しはパレットとは別のUIなので、このファイルと連動させない。
