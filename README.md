# cat-smf-editor

A lightweight app aiming to easily edit SMF (Standard MIDI File). It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

Currently, editing capabilities are very limited.
The reason for releasing it in this state is for rubber duck debugging.

# Past challenges and what this app solves
- Attempts to release CC0 licensed music data, like [The Mutopia Project](https://www.mutopiaproject.org/), are wonderful!
- For serious performances or editing, preparatory steps like launching a DAW are often required.
- Lightweight apps for easy performance and editing often had a user experience that wasn't to my liking.
- Nowadays, if you want a certain UX, you can achieve it with vibe coding.
- That's what I decided to do.

## Features (Detailed additions by AI)

- Playback
  - Toggle synchronization with `Ctrl+, → b` or "Zundamon Playback Sync" in the command palette. If the server doesn't respond via API during synchronized playback, `mascot-render-server.exe` is automatically launched, and automatically launched servers are terminated when the editor closes. Already running servers are used as is and are not terminated when the editor closes. The `exe` is searched for in the editor's directory, then `mascot-render-server/target/release` in a sibling repo during development builds, then `PATH`. In the palette, you can also search with `voicevox` or `ずんだもん` (Zundamon). The ON/OFF state is saved to `status.json` and restored on restart (initially OFF). During playback, it plays a squash-and-stretch animation from the beginning with each quarter note, cutting off mid-motion at the next beat. You can independently adjust length, vertical movement, number of cycles, decay, horizontal spread, and vertical squash amount in the server's `mascot-render-server.toml` (default is 500ms, 3px vertical movement, 1 cycle, 2 decay, 0.1 horizontal, 0.05 vertical), and it hot-reloads on save. The mouth opens and closes only during the note intervals of the target Zundamon vocal track. It does not lip-sync for other characters, non-target tracks, or rests. It follows tempo changes, mid-playback starts, and A-B repeat, and deactivates on stop, OFF, exit, or communication loss. Mouth images may be prepared with a delay on first use, but playback is not paused while waiting for visuals. Mouth opening/closing is a 2-frame toggle based on the server's default cycle, not mora-synchronized. It does not perform beat synchronization for squash-and-stretch with SMPTE division. It continues playback without waiting for server launch/connection, and logs launch/communication errors to `error.log`.

  - `audio-command`, `audio-stop`, `audio-diagnostic` are recorded to the same `error.log` for audio investigation. PID, command number, track number, audio-side reception number, approximately 1-second interval output peak, per-track peak, callback count, lock contention, and failure points can be tracked. The order of per-track peaks corresponds to the track list in the preceding `audio-command`. If peaks remain after stopping, a residual sound from the sound source/effect is suspected; if the command number does not advance, audio-side reception stopping is suspected (this information does not definitively identify the cause). `failure_bits` is the sum of 1=audio processing failure, 2=device error, 4=track render failure, 8=track non-finite value, 16=mix non-finite value, 32=master failure, 64=post-master non-finite value. # Local Build and Run

Place editor, `cat-plugin-player`, `uapmd`, `clap-mml-render-tui`, `clap-mml-play-server`, `mascot-render-server` in the same parent directory.
```powershell
cargo build --release --locked
& ./target/release/cat-smf-editor.exe 'X:\music\song.mid'
```

To explicitly specify the player, launch with `& ./target/release/cat-smf-editor.exe --player 'X:\projects\cat-plugin-player\target\release\cat-plugin-player.exe'`. No environment variable setup is required.

The search order for the player used for cache miss restoration requests and browser selections is `--player <path>`, the same directory as the editor's exe, sibling repo's `cat-plugin-player/target/release/cat-plugin-player.exe`, then `PATH`. Sibling repo search occurs when the editor's exe is in `target/debug` or `target/release` and does not depend on the working directory. If the specified path is invalid, it does not silently switch to another location. If playback restoration fails on launch and the player is also not found, the [distribution ZIP](https://github.com/cat2151/cat-plugin-player/releases/download/v0.1.0/cat-plugin-player-0.1.0-windows-x64.zip) is automatically downloaded and placed in the same directory as the editor's exe. The downloaded player's integration features are checked before placement; unsupported older distributions are not placed, and a message indicating the need for an update is displayed. Existing players are not overwritten. The player's license agreement screen is not shown; copyright notices are saved as `cat-plugin-player-LICENSE.txt` inside a `cat-smf-editor-licenses` folder created within the Windows Desktop (including locations moved to like OneDrive). If a file with the same name but different content exists, it is preserved with a distinguishing suffix. If download or write fails, you can choose to retry or manually download.

If playback restoration fails on launch and no sound source is detected, the Surge XT terms of use can be reviewed from a screen common with cat-plugin-player, and after agreement, installed via winget. This also applies if only effects are involved. If existing sound sources are present, this guide is not shown. If saved tones can be restored for playback, player discovery and sound source list scanning are not awaited. Even if restoration fails, if the player's sound source cache records existing sound sources, scanning is omitted. After installation, it rescans and proceeds to normal MIDI restoration and file selection. It can be deferred with `Later` / `Esc`. Installation that has already started continues even after closing the guide. Tab / Shift+Tab moves between items; Enter / Space selects buttons. Failure details are shown on screen and in `error.log`; if winget is not available, manual download locations are provided. You can retry from `Setup` on the player selection error screen. Write permissions for the ZIP placement location and Windows permission confirmation for Surge XT installation may be required. See [ADR 0009](docs/adr/0009-first-run-dependencies.md) for configuration.

Each app bundles the host DLL corresponding to its build into its exe. The editor's DLL extraction location is `%LOCALAPPDATA%\cat-smf-editor\cache\native\`. The `cache/` subdirectory contains only regeneratable data; after deletion, necessary items are regenerated. `startup.json` (holding the path of the previous MID) and `status.json` (holding operation positions, display settings, browser selections) are separated; only `startup.json` is read before audio playback on launch. `status.json` also holds a path to match the target song for operation positions. Both, along with `settings.toml`, history, logs, and `backup/` from MIDI saves, are kept outside the cache. The editor does not borrow DLLs from installed players. See [ADR 0003](docs/adr/0003-shared-host-player-selection.md) for commonality and save contracts, and [release workflow](docs/release-workflow.md) for distribution configuration.
