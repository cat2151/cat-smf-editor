# cat-smf-editor

A lightweight application aiming to easily edit SMF (Standard MIDI File). It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

Currently, it has very limited editing capabilities.
It is being released in this state for the purpose of rubber ducking.

# Past Challenges and What This App Solves
- Attempts to publish CC0-licensed music data, like [The Mutopia Project](https://www.mutopiaproject.org/), are wonderful!
- For serious performance and editing, often extensive preparation, such as launching a DAW, is required.
- Lightweight apps for easy performance and editing often had a user experience that was not for me.
- In modern times, if you want a specific UX, you can achieve it through vibecoding.
- So I decided to do just that.

- Timbre

Immediately after change, the new change amount is displayed for 500ms as a toast with a cyan frame and dark background, immediately to the upper right of the current position of the selected macro's bar; continuous changes replace with the latest value and extend display time. Prepending a number to `hjkl` performs the operation that many times; `99l` is equivalent to pressing `l` 99 times. During number input, `Esc` cancels only the prefix. For Vaporizer2, since polarity is per mod matrix row, it's displayed as bipolar only if all rows where that macro appears are bipolar. Sound source-derived display strings, API send/receive values, and exposed ranges are also shown, without hiding inconsistencies. It immediately auditions by A-B repeating all tracks in the current measure. `D` duplicates the current Variation for editing; `PageUp/PageDown` or clicking a number switches to compare (max 128, wraps at ends). `r` references all Variations (including current edited value) and randomizes all macros of the current Variation within each macro's min/max range, auditioning immediately. `Shift+R` randomizes over the entire sound source range as before. Both write only to the current Variation, not affecting others. `Enter` activates the selected Variation and saves all Variations and the selected number to the same dedicated meta at the track's beginning, then exits. Reopening restores selection and each Variation. `Esc` or `×` cancels the entire current edit. Confirmation/exit and cancel keys are always displayed on screen; `?` / `F1` opens/closes the help overlay; `Esc` closes only help. Editing keys are not accepted while help is displayed. The entire confirmation can be undone with one Undo action. Automation tracks are not created; if automation for the same macro exists during normal playback, it takes precedence. Replacing timbre or deleting a layer cancels its fixed values and all Variations. Changing bipolar mode, editing the entire instance state, and the sound source GUI are not supported ([ADR 0014](docs/adr/0014-surge-macro-edit.md), [ADR 0015](docs/adr/0015-vaporizer2-macro-edit.md), [ADR 0016](docs/adr/0016-six-sines-floe-macro-edit.md)).

The upper section displays notes, and the lower section uses quadratic Bézier editing common to the tempo curve. Left-clicking empty space or `a` adds a yellow point; select a Variation from the overlay that appears. `↑/↓` selects candidates, `Enter` confirms, `Esc` cancels. Clicking a candidate also confirms. `h/l` selects points, `j/k` selects controls, `Enter` edits, `Delete` or right-clicking a point deletes it; `r` / `Esc` closes the screen. Dragging a point changes time, dragging a control changes interpolation shape. Purple controls can move beyond the values of the two end points or the upper/lower limits of the Variation list, and can also be adjusted vertically with `Enter` and `↑/↓`. Out-of-range controls are saved/restored, and macro values during playback are clipped to the sound source's valid range. Based on the macro values of two adjacent Variation points, all macros change along the same curve; before the first point and after the last point, that Variation is retained. If parameter automation for the same macro exists, it takes precedence. The curve is saved/reloaded to the owner track's dedicated meta, and each edit can be undone. A minimum of two saved Variations is required. `Ctrl+, → u`'s `Macro variation curve always maximized` is saved/restored independently. Opening it starts A-B repeat playback from the beginning to the end of the target track, and repeat is maintained during Variation selection and after curve editing. No time input field is provided. The vertical axis initially has margins above/below points; left-clicking the left `zoom` bar, scrolling up with the wheel, or left-dragging zooms in; right-clicking or scrolling down with the wheel zooms out. Zoom-in is capped at 1.0x initial display; zoom-out can return up to 1.0x. The vertical axis remains centered across all Variations; no vertical scrolling. Time axis zoom/scroll, minimap, follow, and A-B range changes are common with parameter curves. The vertical minimap at the right edge of the event list also overlays curves for each layer of the displayed track in purple. Vertical is time, horizontal is Variation value; out-of-range controls are also displayed, and the time range expands if the curve end is after the last event. It corresponds to Notes/Raw and two-column display panes. Timbre replacement or layer deletion also cancels corresponding curves.

Patch selection from `t` / Program Change row replaces the first layer of the target track; the patch button in the layer overlay replaces only that row. For effects, `x` in the overlay replaces the selected effect (adds if none); `a` adds to the end. Selecting the same effect plugin for a different effect slot is not reflected. Role (top-left) and Preset (bottom-left) in the patch browser, and Category (top-left) and Kind (bottom-left) in the effect browser, are saved independently to `status.json` for each song/track/layer for patches, each song/track for track effects, and each song for master effects, and restored on reopening and next launch. While the patch/effect browser is open, hold time is updated every minute; unused caches are released if not used for 5 minutes after closing. Active sound sources are retained. - Error Investigation
  - Startup, load, save, audio, player, and other errors are appended to `%LOCALAPPDATA%\cat-smf-editor\error.log` with timestamps. Duplicate output is suppressed for each frame while the same error continues to display.
  - `audio-command`, `audio-stop`, `audio-diagnostic` are recorded to the same `error.log` for audio investigation. PID, command number, track number, audio-side reception number, approximately every 1 second output peak, track-specific peak, callback count, lock contention, and failure locations can be tracked. The order of track-specific peaks corresponds to the track list in the preceding `audio-command`. If peaks remain after stopping, a residual sound from the sound source/effect side is suspected; if the command number does not advance, cessation of reception on the audio side is suspected (this information does not confirm the cause). `failure_bits` is the sum: 1=audio processing failure, 2=device error, 4=track render failure, 8=track non-finite value, 16=mix non-finite value, 32=master failure, 64=master post non-finite value. Periodic logs are omitted while callbacks proceed normally with no sound.

# Local Build and Execution

Place the editor, `cat-plugin-player`, `uapmd`, `clap-mml-render-tui`, `clap-mml-play-server`, and `mascot-render-server` in the same parent directory. The editor references the player's common host, initial setup, MML input source, TUI's `chord`/`midi-filter`, play-server's `core-lib`, and mascot-render-server's client/protocol. The MML and chord converters are fetched from Cargo.toml's Git dependencies. If building the player, also prepare the dependencies checkout mentioned in the player's README.

```powershell
cargo build --release --locked
& ./target/release/cat-smf-editor.exe 'X:\music\song.mid'
```

To explicitly specify the player, launch with `& ./target/release/cat-smf-editor.exe --player 'X:\projects\cat-plugin-player\target\release\cat-plugin-player.exe'`. No environment variable setup is required.

The search order for the player used for cache miss restoration requests and browser selection is: `--player <path>`, same directory as the editor's exe, `cat-plugin-player/target/release/cat-plugin-player.exe` in the sibling repository, then `PATH`. Sibling repository search occurs when the editor's exe is in `target/debug` or `target/release`, and does not depend on the working directory. If the specified path is invalid, it does not silently switch to another location. If playback restoration fails on startup and no player is found, it automatically downloads the [distribution ZIP](https://github.com/cat2151/cat-plugin-player/releases/download/v0.1.0/cat-plugin-player-0.1.0-windows-x64.zip) and places it in the same directory as the editor's exe. It verifies the acquired player's compatibility before placement; older, unsupported distribution versions are not placed, and a message indicating the need for an update is displayed. Existing players are not overwritten. The player's license agreement screen is not shown; copyright notices are saved as `cat-plugin-player-LICENSE.txt` inside a `cat-smf-editor-licenses` folder created within Windows' Desktop (including locations moved to like OneDrive). If a file with the same name but different content exists, it is preserved under a different name with a content-identifying suffix. If acquisition or writing fails, you can choose to retry or download manually.

If playback restoration fails on startup and no sound source is detected, the user can review the Surge XT terms of service from a screen shared with cat-plugin-player, and install it via winget upon agreement. This also applies if only effects are involved. It does not prompt if existing sound sources are found. If saved timbres can be restored and played, it does not wait for player discovery or sound source list scanning. Even if restoration fails, if the player's sound source cache contains existing sound sources, scanning is skipped. After installation, it rescans and proceeds to normal MIDI restoration/file selection. It can be dismissed with `Later` / `Esc`. Even if the prompt is closed, ongoing installations continue. Tab / Shift+Tab moves between items, Enter / Space selects buttons. Details of failures are displayed on screen and in `error.log`; if winget is not found, manual download locations are provided. You can retry from `Setup` on the player selection error screen. Write permissions may be needed for ZIP placement, and Windows permission confirmation for Surge XT installation. Refer to [ADR 0009](docs/adr/0009-first-run-dependencies.md) for configuration.

Each application bundles its corresponding host DLL with its executable. The editor's DLL extraction location is `%LOCALAPPDATA%\cat-smf-editor\cache\native\`. The `cache/` directory contains only regeneratable data; upon deletion, necessary items are regenerated. `startup.json` (containing the path of the previous MIDI) and `status.json` (containing operation positions, display settings, and browser selections) are separated, with only `startup.json` read before audio output on startup. `status.json` also retains the path to match the target song for operation positions. Both, along with `settings.toml`, history, logs, and `backup/` during MIDI saving, are kept outside the cache. The editor does not borrow DLLs from installed players. Refer to [ADR 0003](docs/adr/0003-shared-host-player-selection.md) for commonization and saving contracts, and [release workflow](docs/release-workflow.md) for distribution configuration.

# Concept, What It Aims For
- Toy
  - It aims to be more of a toy than an editor.
  - The positioning of this app is roughly: [Toy] >> Educational >> Commercial.
  - Only a very few elements can be edited.
  - The name includes "editor," but never mind that.
- Playback
  - It aims to maintain "playing back in the author's environment" as much as possible.
- Immediate Playback
  - From app launch to sound playback, it feels like 0.2 seconds for a single track. Playback is prioritized to be as fast as possible.
    - Even processes like GUI display preparation are done after the sound.
      - Sound playing before GUI display might be considered the sound version of a splash screen.
- Implement Only My Workflow
  - Due to almost zero development resources, this is a triage.
  - Developing this kind of editor requires enormous development costs.
    - For example, just direction for feature selection (which isn't possible if aiming for standard, so it has to be all-inclusive) for things like Undo, Time Machine, and non-destructive editing to achieve safe editing and a standard UX, along with data model design, operational design, detailed enumeration, verification implementation, and dogfooding, incurs massive development costs.
  - If you're looking for a common "lightweight and standard editor," please look elsewhere.
- From Educational to Experimental
  - It leans more towards educational use than commercial.
  - However, due to the constraints mentioned above, this app leans more towards a toy or experimental use than educational.
- Experimentation, Exploration, Personal Use
  - Destructive changes are frequent.
    - It's a daily occurrence that a file saved yesterday cannot be loaded today.
      - Therefore, please limit use to toy-level.
