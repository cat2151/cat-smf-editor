# cat-smf-editor

A lightweight application aiming to make SMF (Standard MIDI File) editing easy. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

Currently, editing capabilities are very limited.
It is being released in this state for rubber duck debugging purposes.

# Past Challenges and What This App Solves
- Attempts to publish CC0-licensed music data, like [The Mutopia Project](https://www.mutopiaproject.org/), are excellent!
- Serious performance or editing often requires preparation, such as launching a DAW.
- Lightweight apps for casual performance or editing often had a "not for me" user experience.
- In modern times, if you have a desired UX, you can achieve it through vibe coding.
- So, I decided to do that.

- Error Investigation
  - Startup, load, save, audio, player, and other errors are appended with timestamps to `%LOCALAPPDATA%\cat-smf-editor\error.log`. Suppresses duplicate output every frame while the same error continues to be displayed.
  - `audio-command`, `audio-stop`, `audio-diagnostic` are recorded to the same `error.log` for audio investigation. PID, command number, track number, audio-side reception number, approximately 1-second interval output peak, per-track peak, callback count, lock contention, and failure points can be tracked. The order of per-track peaks corresponds to the track list of the immediately preceding `audio-command`. If peaks remain after stopping, residual sound from the sound source/effect is suspected; if the command number doesn't advance, audio-side reception stoppage is suspected (this is not definitive information about the cause). `failure_bits` is the sum of 1=audio processing failed, 2=device error, 4=track render failed, 8=track non-finite value, 16=mix non-finite value, 32=master failed, 64=master-post non-finite value. Periodic logs are omitted while callbacks proceed normally without sound.

# Concept, What We Aim For
- Toy
  - We aim for it to be more of a toy than an editor.
  - The positioning of this app is roughly [Toy] >> Educational >> Commercial.
  - Only a very small number of elements can be edited.
  - Don't mind that "editor" is in the name.
- Sounding
  - We aim to maintain "sounding in the author's environment" as much as possible.
- Immediate Sounding
  - From app launch to sound output, for one track, it's perceptually 0.2 seconds. We've made playback as fast as possible.
    - Processes like GUI display preparation are also done after sound.
      - Sound playing before GUI display might be considered a sound version of a splash screen.
