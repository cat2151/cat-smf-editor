# cat-smf-editor

A lightweight application aiming to easily edit SMF (Standard MIDI File)s. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

Currently, editing capabilities are very limited.
The reason for releasing it in this state is for rubber ducking.

# Past challenges and what this app solves
- Attempts to release CC0 licensed music data, like [The Mutopia Project](https://www.mutopiaproject.org/), are wonderful!
- Serious performances and their editing often require prior setup, such as launching a DAW.
- Lightweight apps for easy performance and editing often had a user experience that wasn't for me.
- In modern times, if you want a certain UX, you can achieve it through vibe coding.
- That's what I decided to do.

  - Toggle playback synchronization with `Ctrl+, → b` or "Zundamon Playback Sync" in the command palette. If the API server does not respond during synchronized playback, `mascot-render-server.exe` will be automatically launched, and automatically launched servers will terminate when the editor closes. Already running servers will continue to be used and will not terminate when the editor closes. The executable is searched for in the following order: the same directory as the editor, `mascot-render-server/target/release` in a sibling repository during a development build, and then `PATH`. In the palette, you can also search with `voicevox` or `zundamon`. ON/OFF status is saved to `status.json` and restored on restart (initially OFF). During playback, it stretches and bounces every quarter note from the beginning, cutting off mid-motion at the next beat. The length, vertical movement, number of cycles, decay, horizontal spread, and vertical squash can be independently adjusted in the server's `mascot-render-server.toml` and hot-reloaded upon saving. Defaults are 500ms, 3px vertical movement, 1 cycle, 2 decay, 0.1 horizontal, 0.05 vertical. The mouth opens and closes only during the note sections of the target Zundamon vocal track. Mouth images may be prepared with a delay on first use, but playback will not stop to wait for the visuals. Mouth opening/closing is a 2-frame switch based on the server's default cycle, not mora-synchronized. SMPTE division does not synchronize the stretch/bounce to beats. Vertical axis and value display are from the sound source; no direct value input field is provided. Top/left `zoom` bars (shared with tempo curve) scale time/value axes. Left-click zooms in by 1.5x, right-click zooms out by 0.66x. Left-dragging a zoom zone expands the selected range to 90% of display width. Wheel on bar zooms that axis; on right/bottom scrollbar, scrolls that axis; otherwise, scrolls time. Scrollbar arrows move half a screen width. Left-dragging on upper notes expands time range; right-click/right-drag adjusts closer end of display range. `PageUp/PageDown` also time-zooms while keeping display center. Minimap allows movement. Note reference, curve, playback position, follow, A-B use the same horizontal axis. Open/close, search, selection, zoom, scroll do not change saved content or Undo. Only drag confirm/edit confirm are bundled into one Undo operation.
  - Parameter automation is SMF format 1 specific; one track references one layer/parameter of its owner by stable ID. CLAP saves plain, VST3 saves normalized values, and does not change the base state of existing patch references. During playback, range audition, seek, and A-B (including owner), values are applied at 64-frame intervals fixed to audio sample positions and at note/point boundaries. Current-track playback on an automation track plays its owner. Deleting the last point leaves the target but deactivates application, restoring the base timbre for normal playback. Conflicting unresolved targets or non-empty curves display the target and reason, stopping playback for the affected scope, and do not substitute another parameter. VOICEVOX, effects, master, and MIDI CC are excluded. Refer to [ADR 0013](docs/adr/0013-instrument-parameter-automation.md) for save contracts and audio timing judgment, and [player ADR 0037](../cat-plugin-player/docs/adr/0037-direct-parameter-automation.md) for native compensation.
  - Restores per-track layers and effects. Same pitches on different tracks are played by independent sound sources. Unconfigured tracks use Surge XT, equivalent to traditional default timbres. SMF GM Program Change is not interpreted as automatic switching to GM sound sources or CC timbre selection.
- Timbre
  - Timbre candidates in the drum screen use existing catalog metadata and common kick/snare/hi-hat/perc classification. Filtered to Surge XT, not limited to Percussion folder. Open candidates in the per-line Instrument field. Filter with Migemo Romanji/Japanese/space-separated AND search, select with up/down keys, `Enter` to confirm, `Esc` to cancel. Catalog is searched in order: TUI local cache, player Surge catalog, public Surge catalog. Regular playback of saved drum tracks does not re-read the catalog.
  - In the command palette, "Surge XT Macro edit", "Vaporizer2 Macro edit", "Six Sines Macro edit", "Floe Macro edit" edit only the active macros (Surge XT: Macro 1-8, Vaporizer2: Custom modulator 1-4 used in mod matrix, Six Sines: Macro 1-6, Floe: Macro 1-4) of the target track/layer with a horizontal bar. For Floe, it targets active Macro 1-4 regardless of CC1 assignment. Drag or `h/l` changes the operation position, `j/k` selects macro, Home/End selects both ends. Left/right change amount is initially 0.125, `[` halves it, `]` doubles it. Immediately after change, the new amount is displayed above the current position of the selected macro bar in a cyan-bordered, dark-background toast for 500ms; continuous changes replace with the latest value and extend display time. Prepending a number to `hjkl` performs the operation that many times; `99l` is same as pressing `l` 99 times. During number input, `Esc` cancels only the prefix. Unipolar values 0-1 and bipolar values -1-1 (center 0) are shown along with the 0-1 operation position, according to each macro's declaration. For Vaporizer2, since polarity is per mod matrix row, it displays as bipolar only if all rows where that macro appears are bipolar. Six Sines macros are always -1 to 1 (center 0) and send those values to the sound source. Display strings from the sound source and API send/receive values and public ranges are also shown, without hiding inconsistencies. It auditions immediately while A-B repeating all tracks of the current measure. `D` duplicates the current Variation for editing; `PageUp/PageDown` or clicking numbers switches to compare (max 128, wraps at ends). `r` references all Variations (including edited value) and randomizes all macros of the current Variation within each macro's min-max range, auditioning immediately. `Shift+R` randomizes across the sound source's full range as before. Both only write to the current Variation, leaving others unchanged. `Enter` activates the selected Variation and saves all Variations and selected number to the same dedicated meta at the track start, then exits. Reopening restores selection and each Variation. `Esc` or `×` cancels the entire current edit. Confirmation/exit and cancel keys are always displayed on screen. `?` / `F1` opens/closes the help overlay; `Esc` closes only help. Edit keys are ignored while help is displayed. The entire confirmation is undoable with one Undo operation. No automation track is created; if automation exists for the same macro in normal playback, that takes precedence. Timbre replacement/layer deletion unassigns fixed values and all Variations for that layer. Bipolar mode changes, instance-wide state editing, and sound source GUI are excluded ([ADR 0014](docs/adr/0014-surge-macro-edit.md), [ADR 0015](docs/adr/0015-vaporizer2-macro-edit.md), [ADR 0016](docs/adr/0016-six-sines-floe-macro-edit.md)).
  - In the command palette, "Macro variation curve" places the target track/layer's Variations on a time axis. The upper section shows notes; the lower section is cubic Bezier editing, shared with the tempo curve. Left-clicking an empty space or `a` adds a yellow point; select a Variation in the on-screen overlay. `↑/↓` selects candidates, `Enter` confirms, `Esc` cancels. Clicking a candidate also confirms. `h/l` moves points, `j/k` moves controls. `Enter` edits, `Delete` or right-click on point deletes. `r` / `Esc` closes the screen. Dragging a point changes its time; dragging a control changes interpolation shape. Purple controls can move beyond the values of adjacent points and the upper/lower limits of the Variation list; `Enter` to edit and `↑/↓` to adjust vertically. Out-of-range controls are saved/restored; macro values during playback are clipped to the sound source's valid range. Macro values for all macros change along the same curve based on the macro values of two adjacent Variation points; before the first point and after the last point, that Variation is retained. If parameter automation exists for the same macro, it takes precedence. The curve is saved/reloaded to/from the owning track's dedicated meta, and each edit is undoable. At least two saved Variations are required. `Ctrl+, → u`'s `Macro variation curve always maximized` is saved/restored independently. When opened, it A-B repeats and continues playback from the beginning to the end of the target track, maintaining repeat during Variation selection and after curve editing. No time input field is provided. The vertical axis has margins above/below points even in the initial state. Left-clicking the left `zoom` bar, scrolling mouse wheel up, or left-dragging zooms in; right-clicking or scrolling mouse wheel down zooms out. Zoom in is capped at 1.0x of initial display; can zoom back to 1.0x from a zoomed-out state. The vertical axis keeps the center of all Variations; no vertical scrolling. Time axis zoom/scroll, minimap, follow, and A-B range changes are shared with the parameter curve. The vertical minimap at the right edge of the event list also overlays curves for each layer of the displayed track in purple. Vertical is time, horizontal is Variation value; displays including out-of-range controls, and expands time range if curve end is after the last event. Corresponds to Notes/Raw and dual-column display panes. Timbre replacement/layer deletion also unassigns corresponding curves.
  - `t` / Program Change line opens cat-plugin-player's patch browser; `a` / `x` from effect overlay opens effect browser. The first time, player launches and stays resident; thereafter, only the browser is brought to front. `now loading...` overlay is displayed in the center of the screen until the first display of each patch/effect. Player's main screen is not displayed. Timbre/effects chosen in the browser are not played by the player but applied to the editor's sound source. During playback, it restarts with new settings from the current position; if stopped, it does not start playback. `t` / Program Change line patch selection replaces the first layer of the target track; patch buttons in the layer overlay replace only that line. For effects, `x` in the overlay replaces the selected effect (adds if none); `a` adds to the end. Selecting the same effect plugin for a different effect slot is not reflected. Top-left Role/bottom-left Preset for patch browser, top-left Category/bottom-left Kind for effect browser are saved independently to `status.json` for each song/track/layer for patches, song/track for track effects, and song for master effects, and restored on reopen and next launch. Effect slots within the same track share selections. For batch patch selection, it uses the selection of the first playing track. Search strings, including Solo/Mute and exclusion conditions, are also saved/restored per target. Even if closed without selecting a timbre, filtering is remembered. Patch list selection is also remembered by patch name and sound source/original patch identification info for each song/track/layer, and the same patch is selected and returned to visible position even if sort order changes. Timbre is not reapplied on selection restoration. Deleted/filtered-out patches are unselected. Deleted Roles/Presets, Categories/Kinds revert to ALL.
  - The editor caches plugin chains used per track; it reuses them when returning to the same configuration. For different timbres, states are reloaded. While patch/effect browsers are open, hold time is updated every minute; unused caches are released if not used for 5 minutes after closing. In-use sound sources are retained. Memory increases during retention; initial generation and after release take time. On song switch, previous song's sound sources are discarded. Master setting changes, audio errors, or sound source resets re-prepare necessary sound sources. Refer to [plugin instance cache](docs/plugin-instance-cache.md) for details.
  - The target of `t` is determined by `Ctrl+, → t`'s two choices, with the current selection indicated by color. `Ctrl+, → ta` (default) applies to all notes on all tracks without confirmation if multiple tracks have notes and all program names are identical; otherwise, it targets only the current track. `Ctrl+, → tc` always targets only the current track. The selection is saved to `%LOCALAPPDATA%\cat-smf-editor\status.json` and restored on next launch. Batch change only alters the patch of the first layer for all tracks with notes, retaining additional layers, octave/dB of each layer, and effect/bypass/volume of each track. For empty layer lists, it adds the first layer. Except for drum tracks, non-batch timbre selection for tracks without Note On events is blocked by an error overlay, prompting to select a playing track.
  - `Esc`, `q` (if not used for text input), `×` in browser, `Enter` to close effect browser only hide the browser; the player does not terminate. `q` in the search field is for text input. Closing the editor also closes the player. If the player terminates mid-session, an error is displayed, and it restarts on the next `t` / `x`.
  - Selections are reflected in the target when the browser is opened (current track, all tracks with notes for batch, conductor for master). Old patch selections received after opening another file, opening another browser, deleting a target layer, or reloading a song after opening the browser are not incorporated.
  - Layer patch reference, octave, dB, mute, solo, and ordered track/master effect reference and bypass are saved to SMF dedicated meta. Restored by plugin format/ID and original patch location/program/preset value; state itself is not stored in SMF. Migration of old state save formats is not performed; known old meta or broken references result in an error. Duplication of external samples or state compatibility across OS/plugin versions is not guaranteed.

On next SMF restoration, valid cache is used first, and only missing patches are restored via the player's hidden generation path. If all cache is valid, player search/launch/catalog scan/generation are unnecessary, and it doesn't depend on `--player` presence. Updates/corruption of plugin and original patch result in a cache miss; octave/dB/track number are not included in the cache key. Sound source instances are not shared between layers. Refer to [ADR 0006](docs/adr/0006-instrument-layers-and-patch-state-cache.md) for details and the subsequent general graph migration policy.

The original environment is passed to the browser and state generation player. Can be disabled with `CMRT_SURGE_MINIMAL_DATA_HOME=0`. Refer to [ADR 0012](docs/adr/0012-surge-minimal-data-home.md) for verified timbres/FX, scope of application, and measurement results.
- Error Investigation
  - Startup, load, save, audio, player, and other errors are appended to `%LOCALAPPDATA%\cat-smf-editor\error.log` with timestamps. Duplicate output is suppressed for every frame as long as the same error continues to display.
  - For audio investigation, `audio-command`, `audio-stop`, `audio-diagnostic` are recorded to the same `error.log`. PID, command number, track number, audio-side reception number, output peak every ~1 second, track-specific peak, callback count, lock contention, and failure locations can be traced. The order of track-specific peaks corresponds to the track list in the preceding `audio-command`. If peaks remain after stopping, it might indicate residual sound from the sound source/effect; if the command number doesn't advance, it might indicate reception stopping on the audio side (this is not definitive information for determining the cause). `failure_bits` is the sum of 1=audio processing failure, 2=device error, 4=track render failure, 8=track non-finite value, 16=mix non-finite value, 32=master failure, 64=post-master non-finite value. Periodic logs are omitted while callbacks proceed normally with no sound.
- Effect Routing
  - Master effects support SMF format 1 and are saved/restored to/from the conductor (first track)'s dedicated meta. After applying and mixing each track's effects and volume, master effects and Master auto gain are processed in that order. Effects selected in the master effect browser are applied only to the master. Master support for format 0/2 has not been added. Reasons and saving format are recorded in [ADR 0004](docs/adr/0004-master-effects-in-conductor-track.md).
  - Track effects and master effects are edited in dedicated overlays. The overlay draws the signal flow vertically (track: instrument layer → effect → mixer; master: track group → effect → Master auto gain → output). Effects can be added/replaced (browser), reordered by dragging or `Shift+j/k`, bypassed per effect, or deleted. Bypass is saved per effect to SMF and switches without stopping playback. Entry points are `x` in the main screen and mixer, and effect names in track headers and mixer. The configuration is used for in-editor audition, range playback, and all-track playback. Reasons are recorded in [ADR 0007](docs/adr/0007-effect-chain-on-uapmd-graph.md).

# Local Build and Run

Place the editor, `cat-plugin-player`, `uapmd`, `clap-mml-render-tui`, `clap-mml-play-server`, and `mascot-render-server` in the same parent directory. The editor references the player's common host/first-time setup/MML input source, TUI's `chord`/`midi-filter`/`patches`, play-server's `core-lib`, and mascot-render-server's client/protocol. MML and chord converters are obtained from Cargo.toml's Git dependencies. If building the player, also prepare the dependencies checkout mentioned in the player's README.

```powershell
cargo build --release --locked
& ./target/release/cat-smf-editor.exe 'X:\music\song.mid'
```

To explicitly specify the player, launch with `& ./target/release/cat-smf-editor.exe --player 'X:\projects\cat-plugin-player\target\release\cat-plugin-player.exe'`. No environment variable setup is needed.

The search order for the player used for cache miss restoration requests and browser selections is `--player <path>`, the same directory as the editor's executable, `cat-plugin-player/target/release/cat-plugin-player.exe` in a sibling repository, and then `PATH`. Sibling repository search is performed when the editor's executable is in `target/debug` or `target/release`, and does not depend on the working directory. If the specified path is invalid, it will not silently switch to another location. If playback restoration fails on startup and no player is found, [the distribution ZIP](https://github.com/cat2151/cat-plugin-player/releases/download/v0.1.0/cat-plugin-player-0.1.0-windows-x64.zip) is automatically downloaded and placed in the same directory as the editor's executable. The functionality of the downloaded player is checked before placement; unsupported older distribution versions are not placed, and a message indicating the need for an update is displayed. Existing players are not overwritten. The player's license agreement screen is not shown. Copyright notices are saved as `cat-plugin-player-LICENSE.txt` inside a `cat-smf-editor-licenses` folder created within the Windows Desktop (including locations moved to OneDrive, etc.). If files with the same name but different content exist, they are preserved with a distinct suffix. If download/write fails, retry or manual download can be chosen.

If playback restoration fails on startup and no sound source is detected, the user can review the Surge XT terms of service from a screen shared with cat-plugin-player, and install it via winget after agreeing. This also applies if only effects are needed. If an existing sound source is available, this prompt is not shown. If saved timbres can be restored for playback, player search or sound source list scanning is not awaited. Even if restoration fails, if an actual sound source is recorded in the player's sound source cache, scanning is skipped. After installation, it rescans and proceeds to normal MIDI restoration/file selection. It can be deferred with `Later` / `Esc`. Even if the prompt is closed, an ongoing installation continues. Tab / Shift+Tab moves between items, Enter / Space selects buttons. Failure details are shown on screen and in `error.log`; if winget is not available, manual download instructions are provided. It can also be restarted from `Setup` in the player selection error screen. Write permissions for the ZIP placement location and Windows permission confirmation for Surge XT installation may be required. Refer to [ADR 0009](docs/adr/0009-first-run-dependencies.md) for the configuration.

Each application bundles its corresponding host DLL with the executable. The editor's DLL extraction location is `%LOCALAPPDATA%\cat-smf-editor\cache\native\`. The `cache/` directory contains only regeneratable data; after deletion, necessary items are regenerated. `startup.json`, which holds the path of the previous MID, and `status.json`, which holds operation positions, display settings, and browser selections, are separated. Before sound generation on startup, only `startup.json` is read. `status.json` also retains the path to match the target song for operation positions. Both, along with `settings.toml`, history, logs, and `backup/` during MIDI saving, are kept outside the cache. The editor does not borrow DLLs from installed players. Refer to [ADR 0003](docs/adr/0003-shared-host-player-selection.md) for commonality and save contracts, and [release workflow](docs/release-workflow.md) for distribution configuration.

# Concepts and Goals
- Toy
  - Aiming for a toy rather than a full editor.
  - The positioning of this app is roughly [Toy] >> Educational >> Commercial.
  - Only a very small number of elements can be edited.
  - The name includes "editor," but don't mind it.
- Playability
  - Aim to maintain "playability in the author's environment" as much as possible.
- Immediate Playback
  - From app launch to sound output for a single track is a sensory 0.2 seconds. Playback is prioritized to be the fastest.
    - Processes like GUI display preparation are done after the sound.
      - Sound playing before GUI display might be considered a "splash screen for sound."
- Implement only the workflows I use
  - Due to almost zero development resources, this is a triage.
  - Developing this kind of editor requires enormous development costs.
    - For example, ensuring safe editing and a standard UX with features like undo, time travel, and non-destructive editing requires immense development costs just for data model design, operation design, elicitation, verification implementation, and dogfooding to direct feature selection (which is impossible if aiming for standard, so it has to be all-inclusive).
  - If you're looking for a common "lightweight and standard editor," please look elsewhere.
- From educational to experimental
  - It leans more towards educational use than commercial use.
  - However, due to the above constraints, this app leans more towards a toy or experimental use than educational.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will occur.
    - Files saved yesterday may not load today; this will be commonplace.
      - Therefore, limit use to a toy level.

  - Toy: I want to edit only a specific part intensively. Timbre and effects, tempo curve, arpeggio, fine-tune each note on the piano roll. Prioritize a quick edit and verification cycle, with fully automatic load/save without manual operation → This app targets a very small subset of that workflow.
  - Quickly browse and play, quickly visualize content. A lightweight browser or viewer.
  - Want to make a small change. Guarantee that everything else remains perfectly original, with diff visualization for that purpose. A lightweight editor.

    - No, I think it's better to compose with a standard modern app rather than an SMF editor.
  - Serious composition and arrangement.

    - Furthermore, highly advanced undo, time travel, and non-destructive editing are essential at a very high level.

# Out of Scope, Not Aimed For
- DAW
  - Directly read/write not just SMF but also DAW projects and other famous DAW projects, allowing editing, and of course, audio.
- Plugins
  - Freely extend all editor functions with plugins.
- Scripting
  - Freely extend all editor functions with scripts.
- Standard
  - Cover 200% of the appearance and behavior of standard SMF editors and DAWs. Complete superset of all editors and DAWs.
- Features
  - Include every possible feature. Usable for all purposes.
- Compatibility
  - Complete data compatibility.
    - Able to load all SMF files, import all DAW projects.
    - Export supports all music data and all DAW projects.
  - Complete setting compatibility. Able to load and operate with all past settings.
- Robustness
  - Absolutely no bugs no matter what. The app never crashes.
- Convenience
  - Pursue convenience and ease of use to the extreme.
- Performance
  - Operate at high speed with no CPU load in any environment. Audio never cuts out.
- Requests
  - Respond immediately to all user requests.
