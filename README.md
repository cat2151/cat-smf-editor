# cat-smf-editor

A lightweight application aiming for easy editing of SMF (Standard MIDI File) data. It utilizes [UAPMD](https://github.com/atsushieno/uapmd) and is written in Rust.

Currently, editing capabilities are very limited.
This release is primarily for rubber ducking purposes.

# Past Challenges and What This App Solves
- Efforts to publish CC0 licensed music data, like [The Mutopia Project](https://www.mutopiaproject.org/), are fantastic!
- For serious performance and editing, significant preparation is often required, such as launching a DAW.
- Lightweight apps for casual performance and editing often didn't quite match my desired user experience.
- In modern times, if you have a desired UX, you can achieve it through vibe coding.
- So, I decided to do just that.

  - Toggle Zundamon playback synchronization with `Ctrl+, → b` or from the command palette's "Zundamon Playback Link". Already running servers will be used as-is and will not terminate when the editor closes. The executable is searched in the order of the editor's directory, `mascot-render-server/target/release` in a sibling repo for development builds, then `PATH`. In the palette, you can also search with `voicevox` or `Zundamon`. The ON/OFF state is saved to `status.json` and restored on restart (initial state is OFF). During playback, expansion and contraction occur from the beginning at every quarter note, and any intermediate movement is cut off at the next beat. The length, vertical movement, number of cycles, decay, horizontal spread, and vertical squash can be adjusted independently in the server's `mascot-render-server.toml` under `musical_squash_bounce`. Saving this file triggers a hot reload. Defaults are 500ms, 3px vertical movement, 1 cycle, 2 decay, 0.1 horizontal, and 0.05 vertical. Mouth images may be prepared with a delay on the first use, but playback will not stop to wait for the visual. Mouth opening and closing uses a 2-frame switch based on the server's default cycle, not mora synchronization. For SMPTE division, beat synchronization for expansion/contraction is not performed. Current-track playback for an automation track plays its owner. Deleting the last point removes the application while retaining the target, restoring the default timbre for regular playback. Unresolved targets or conflicts with non-empty curves display the target and reason, stop playback for the affected scope, and do not substitute another parameter. VOICEVOX, effects, master, and MIDI CC are not supported. Refer to [ADR 0013](docs/adr/0013-instrument-parameter-automation.md) for saving contracts and audio timing judgment, and [player ADR 0037](../cat-plugin-player/docs/adr/0037-direct-parameter-automation.md) for native patching.
  - Instrument layers and effects per track are restored, and the same pitch on different tracks sounds with independent sound sources. Unconfigured tracks use Surge XT, equivalent to the traditional default timbre. SMF GM Program Change is not interpreted as automatic switching to GM sound sources or timbre selection via CC.
- Timbre
  - "Surge XT Macro edit" from the command palette allows editing only Macro 1-8 currently in use for the target track/layer, using horizontal bars. Drag or `h/l` to change the operation position, `j/k` for macros, Home/End for both ends. Left/right change amount defaults to 0.125; `[` halves it, `]` doubles it. Immediately after change, the new change amount is displayed as a cyan-framed toast with a dark background for 500ms, just above and to the right of the current position of the selected macro's bar. Continuous changes replace with the latest value and extend display time. Prepending `hjkl` with a number performs the operation that many times; `99l` is equivalent to pressing `l` 99 times. While inputting a number, `Esc` cancels only the prefix. Unipolar macros display values from 0-1, bipolar from -1-1 (center 0), along with the operation position 0-1, as declared by each macro. Display strings from the sound source, API send/receive values, and published ranges are also shown, without hiding inconsistencies. It previews instantly, A-B repeating all tracks in the current bar. `D` duplicates the current Variation for editing, and `PageUp/PageDown` or clicking the number switches to compare (up to 128, wraps at ends). `r` randomizes all macros of the current Variation within the min-max range of each macro, referring to all Variations (including edited values), and previews instantly. `Shift+R` randomizes across the sound source's full range, as before. Both only write to the current Variation; other Variations are unchanged. `Enter` activates the selected Variation and saves all Variations and the selected number to the same dedicated meta at the start of the track, then exits. Reopening restores the selection and each Variation. `Esc` or `×` cancels the entire current edit. Confirmation/exit and cancellation keys are always displayed on screen. `?` / `F1` opens/closes the help overlay; `Esc` closes only the help. Editing keys are ignored while help is displayed. The entire confirmation can be undone in one step. No automation track is created; if the same macro has automation during normal playback, that takes precedence. Replacing timbre or deleting a layer cancels its fixed values and all Variations. Changing bipolar mode, editing instance-wide state, and the Surge XT GUI are not supported (see [ADR 0014](docs/adr/0014-surge-macro-edit.md)).
  - "Macro variation curve" from the command palette places Variations of the target track/layer on a time axis. The upper section displays notes, and the lower section uses a quadratic Bézier editor common with the tempo curve. Left-click on a blank space or `a` adds a yellow point, and an overlay appears to select a Variation. `↑/↓` selects candidates, `Enter` confirms, `Esc` cancels. Clicking a candidate also confirms. `h/l` selects points, `j/k` selects controls, `Enter` opens edit mode, `Delete` or right-click a point deletes it. `r` / `Esc` closes the screen. Dragging a point changes its time; dragging a control changes the interpolation shape. Purple controls can move beyond the values of the two end points or the upper/lower limits of the Variation list; `Enter` opens edit mode to adjust them vertically with `↑/↓`. Out-of-range controls are saved/restored, and macro values during playback are clipped to the sound source's valid range. Based on the macro values of two adjacent points' Variations, all macros change along the same curve. Before the first point and after the last point, the Variation is held. If parameter automation for the same macro exists, that takes precedence. The curve is saved to the owner track's dedicated meta and reloaded, and each edit can be undone. A minimum of two saved Variations is required. `Ctrl+, → u`'s `Macro variation curve always maximized` is saved and restored independently. When opened, it A-B repeats playback of the target track from start to end, maintaining the repeat during Variation selection and after curve editing. No time input field is provided. The vertical axis initially has padding above/below points. Left-clicking, upward mouse wheel, or left-dragging the left `zoom` bar zooms in; right-clicking or downward mouse wheel zooms out. Zoom-in is capped at 1.0x the initial display; it can return to 1.0x from a zoomed-out view. The vertical axis remains centered on all Variations, and no vertical scrolling occurs. Time axis zoom, scroll, minimap, follow, and A-B range changes are common with the parameter curve. The vertical minimap on the right edge of the event list also overlays each layer's curve in purple. Vertically, it's time; horizontally, it's Variation value. It displays even out-of-range controls and extends the time range if the curve end is after the last event. It corresponds to Notes/Raw and two-column display panes. Timbre replacement or layer deletion also cancels corresponding curves.
  - `t` or a Program Change line opens the cat-plugin-player's patch browser. `a` or `x` from the effect overlay opens the effect browser. The first time, the player is launched and remains resident; thereafter, only the browser is brought to the foreground. Until the first display of the patch/effect browser, a `now loading...` overlay is shown in the center of the screen. The player's main screen is not displayed. The timbre/effect chosen in the browser is reflected in the editor's sound source, not played by the player. If playing, it restarts playback with the new settings from the current position. If stopped, it does not start playback. Patch selection via `t` or Program Change line replaces only the first layer of the target track. The patch button in the layer overlay replaces only that line. Selecting the same effect plugin for a different effect slot is not reflected. The patch browser's top-left Role and bottom-left Preset, and the effect browser's top-left Category and bottom-left Kind, are saved independently to `status.json` for each patch (per song, track, and layer), track effect (per song and track), and master effect (per song). They are restored when reopened and on the next launch. Effect slots within the same track share selections. For batch patch selection, the selection of the first playing track is used. Search strings, including Solo/Mute and exclusion conditions, are also saved and restored for the same targets. Even if the browser is closed without selecting a timbre, filters are remembered. Patch list selection is also remembered per song, track, and layer by patch name and sound source/original patch identification information, and restores the same patch to visible position even if the sort order changes. Timbre is not reapplied during selection restoration. Deleted patches or patches outside filter scope are unselected. Deleted Roles/Presets or Categories/Kinds revert to ALL.
  - The editor caches the plugin chain used per track and reuses it when returning to the same configuration. For different timbres, it reloads the state. While patch/effect browsers are open, the retention time is updated every minute. If not used for 5 minutes after closing, unused caches are released. In-use sound sources are retained. Memory usage increases during retention, and generation time is longer initially and after release. When switching songs, the previous song's sound sources are discarded. Master setting changes or sound source resets due to audio errors prepare necessary sound sources again. Refer to [Plugin Instance Cache](docs/plugin-instance-cache.md) for details.
  - The target of `t` is determined by two choices from `Ctrl+, → t`. The current selection is indicated by color. `Ctrl+, → ta` (default) changes the patch for the first layer of all tracks with notes, without confirmation, if multiple tracks have notes and all program names are identical. Otherwise, it targets only the current track. `Ctrl+, → tc` always targets only the current track. The selection is saved to `%LOCALAPPDATA%\cat-smf-editor\status.json` and restored on the next launch. Batch changes only modify the patch of the first layer of all tracks with notes, retaining additional layers, octave/dB of each layer, and effects/bypass/volume of each track. If an empty layer list, it adds the first layer. Other than batch, timbre selection for tracks without Note On events is stopped with an error overlay, prompting the user to select a playing track.
  - `Esc`, `q` (if not used for text input), the browser's `×`, and `Enter` to close the effect browser only hide the browser; they do not terminate the player. `q` in the search field is for text input. Exiting the editor terminates the player. If the player terminates unexpectedly, an error is displayed, and it restarts on the next `t` or `x`.
  - Selections are reflected in the target that was active when the browser opened (current track, all tracks with notes for batch, conductor for master). Old patch selections received after opening another file, opening another browser, deleting the target layer, or reloading the song are not applied.
  - Layer patch references, octave, dB, mute, solo, and ordered track/master effect references and bypass are saved to dedicated SMF meta. They are restored by plugin format/ID and original patch position/program/preset value; the state body itself is not stored in the SMF. Migration of old state save formats is not performed, and known old meta or broken references result in errors. Duplication of external samples or state compatibility across OS/plugin versions is not guaranteed.
  - Used states are retained even after switching songs or patches, and saved to `%LOCALAPPDATA%\cat-smf-editor\cache\patch-states-v1\` on exit. For subsequent SMF restorations, valid caches are used first, and only missing patches are restored via the player's hidden generation path. If all caches are valid, player discovery, launch, catalog scanning, and generation are unnecessary, and it does not depend on the presence of `--player`. Plugin and original patch updates/corruption result in a cache miss. Octave, dB, and track number are not included in the cache key. Sound source instances are not shared between layers. Refer to [ADR 0006](docs/adr/0006-instrument-layers-and-patch-state-cache.md) for details and the subsequent general graph migration policy.
  - Surge XT reduces scanning of patch, FX preset, and wavetable lists for playback instances, retains the initial patch, and restores timbre and wavetables from the saved state. The original environment is passed to the browser and state generation player. This can be disabled with `CMRT_SURGE_MINIMAL_DATA_HOME=0`. Refer to [ADR 0012](docs/adr/0012-surge-minimal-data-home.md) for verified timbres, FX, scope of application, and measurement results.
- Error Investigation
  - Errors during startup, loading, saving, audio, or player operations are appended with timestamps to `%LOCALAPPDATA%\cat-smf-editor\error.log`. Duplicate outputs are suppressed for errors that continuously appear every frame.
  - `audio-command`, `audio-stop`, and `audio-diagnostic` are also recorded to the same `error.log` for audio investigation. You can track PID, command number, track number, audio-side reception number, output peak (approximately every 1 second), track-specific peak, callback count, lock contention, and failure locations. The order of track-specific peaks corresponds to the track list in the preceding `audio-command`. If peaks remain after stopping, it suggests residual sound from the sound source/effect side. If the command number doesn't advance, it suggests audio-side reception has stopped (this information does not confirm the cause). `failure_bits` is the sum: 1=audio processing failure, 2=device error, 4=track render failure, 8=track non-finite value, 16=mix non-finite value, 32=master failure, 64=post-master non-finite value. Periodic logs are omitted while callbacks proceed normally with no sound.
- Effect Routing
  - Master effects are supported for SMF format 1, saved and restored to a dedicated meta in the conductor track (first track). After applying track effects and volume, then mixing, master effects are processed, followed by Master auto gain. Effects selected in the master effect browser are applied only to the master. Master support for format 0/2 has not been added. Reasons and save format are recorded in [ADR 0004](docs/adr/0004-master-effects-in-conductor-track.md).
  - Track effects and master effects are edited using dedicated overlays. The overlay depicts the signal flow vertically (track: instrument layer → effect → mixer; master: track group → effect → Master auto gain → output). Effects can be added, replaced (via browser), reordered by dragging or `Shift+j/k`, bypassed individually, or deleted. Bypass is saved per effect to SMF and toggles without stopping playback. Entry points are `x` in the main screen and mixer, and the effect name in the track header and mixer. This configuration is used for in-editor preview, range playback, and all-track playback. The reasons are recorded in [ADR 0007](docs/adr/0007-effect-chain-on-uapmd-graph.md).

# Local Build and Execution

Place the editor, `cat-plugin-player`, `uapmd`, `clap-mml-render-tui`, `clap-mml-play-server`, and `mascot-render-server` in the same parent directory. The editor references the player's common host, initial setup, MML input source, TUI's `chord` / `midi-filter`, play-server's `core-lib`, and mascot-render-server's client / protocol. The MML and chord converters are fetched from Git dependencies in Cargo.toml. If building the player, also prepare the dependencies checkout mentioned in the player's README.

```powershell
cargo build --release --locked
& ./target/release/cat-smf-editor.exe 'X:\music\song.mid'
```

To explicitly specify the player, launch with `& ./target/release/cat-smf-editor.exe --player 'X:\projects\cat-plugin-player\target\release\cat-plugin-player.exe'`. No environment variable setup is required.

The search order for the player used for cache miss restoration requests and browser selections is: `--player <path>`, the same directory as the editor's exe, sibling repo's `cat-plugin-player/target/release/cat-plugin-player.exe`, then `PATH`. Sibling repo search is performed when the editor's exe is in `target/debug` or `target/release` and does not depend on the working directory. If the specified path is invalid, it will not silently switch to another location. If playback cannot be restored on launch and the player is not found, the [distribution ZIP](https://github.com/cat2151/cat-plugin-player/releases/download/v0.1.0/cat-plugin-player-0.1.0-windows-x64.zip) is automatically downloaded and placed in the same directory as the editor's exe. The downloaded player's integration features are checked before placement; old, unsupported distribution versions are not placed, and a message indicating the need for an update is displayed. Existing players are not overwritten. The player's license agreement screen is not shown; copyright notices are saved as `cat-plugin-player-LICENSE.txt` inside a `cat-smf-editor-licenses` folder created within the Windows Desktop (including locations moved to, like OneDrive). If a file with the same name but different content exists, it is preserved under a different name with a content-identifying suffix. If download or writing fails, you can choose to retry or manually download.

If playback cannot be restored on launch and no sound source is detected, the Surge XT terms of service can be reviewed from a screen common to cat-plugin-player. After agreement, it can be installed via winget. This also applies if only effects are involved. If existing sound sources are present, this prompt is not displayed. If saved timbres can be restored for playback, player search and sound source list scanning are not awaited. Even if restoration fails, if the player's sound source cache records existing sound sources, scanning is skipped. After installation, it rescans and proceeds to regular MIDI restoration/file selection. It can be deferred with `Later` or `Esc`. Initiated installations continue even after closing the prompt. `Tab` / `Shift+Tab` moves between items, `Enter` / `Space` selects buttons. Failure details are shown on screen and in `error.log`. If winget is unavailable, manual download locations are provided. You can also retry from `Setup` on the player selection error screen. Write permissions may be needed for the ZIP placement location, and Windows permission confirmation may be required for Surge XT installation. Refer to [ADR 0009](docs/adr/0009-first-run-dependencies.md) for the configuration.

Each application bundles its corresponding host DLL with the exe. The editor's DLL extraction target is `%LOCALAPPDATA%\cat-smf-editor\cache\native\`. Only regeneratable data resides under `cache/`; after deletion, necessary items are regenerated. `startup.json` (containing the path of the previous MIDI) and `status.json` (containing operation positions, display settings, and browser selections) are separated. Only `startup.json` is read before audio playback on launch. `status.json` also holds a path to verify the target song for operation positions. Both, along with `settings.toml`, history, logs, and `backup/` from MIDI saves, are kept outside the cache. The editor does not borrow DLLs from installed players. Refer to [ADR 0003](docs/adr/0003-shared-host-player-selection.md) for commonality and saving contracts, and [release workflow](docs/release-workflow.md) for distribution configuration.

# Concept, Goals
- Toy
  - We aim for a toy rather than an editor.
  - The positioning of this app is roughly: [Toy] >> Educational >> Commercial.
  - Only a very small number of elements can be edited.
  - The name includes "editor," but don't mind it.
- Playback
  - We aim to maintain "playback in the author's environment" as much as possible.
- Immediate Playback
  - From app launch to sound playback, it's a perceived 0.2 seconds for one track. We prioritize the fastest possible playback.
    - Processes like GUI display preparation are also performed after the sound.
      - Sound playing before GUI display might be considered a sound version of a splash screen.
- Implement only the workflows I use
  - Due to almost zero development resources, this is a triage.
  - Developing this kind of editor requires enormous development costs.
    - For example, just for ensuring safe editing and standard UX with features like undo, time machine, and non-destructive editing, the development cost is immense, requiring data model design, operational design, scoping, verification implementation, dogfooding, and directing feature selection (which isn't really possible if aiming for standard, so you have to include everything).
  - If you're looking for a common "lightweight and standard editor," please look elsewhere.
- From educational to experimental
  - It leans more towards educational use than commercial use.
  - However, due to the constraints above, this app leans more towards a toy or experimental tool than educational.
- Experimentation, Exploration, Personal Use
  - Frequent breaking changes will occur.
    - It will be commonplace for files saved yesterday not to load today.
      - So, please limit usage to a "toy" level.
